Driver-neutral core

The UI never learns a driver’s name.

A driver declares what it is. The interface reads that declaration and picks a view, so a document store gets a document tree and a log source gets a live stream, with no branch on a driver name anywhere in the app. Pick a driver to see it.

MCP governance

Give an agent a connection, not your database.

Every MCP call is classified before it touches anything. A policy engine decides per role and per connection, and the risky ones wait for a human. Pick a call and follow it through.

MCP clientCalls a tool over stdio with its client id.

Writes are parked as a pending execution. It runs only after someone approves it in DBFlux, and the approval is audited too.

Four rules the code enforces
01

Keyboard before pointer

If an action exists, it has a binding and a command-palette entry. No workflow depends on the mouse.

02

No driver names in the UI

Category, query language and capability flags decide what renders. New behaviour adds a seam to the core.

03

Dense over decorative

Cut corners on controls, hard edges on data, one accent colour. Screen space belongs to your data.

04

Nothing runs unrecorded

Queries, hooks, scripts and agent calls share one audit log, redacted by default and yours alone.
