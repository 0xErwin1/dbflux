Import wizard: error states

A file that cannot be read never starts a run. Where the user can fix it on the current step, the wizard stays there with the options editable; otherwise it stays on the picker. Every error block ends with what to do next, and a disabled Continue says why in the footer. A failed run ends on a Done step with a closing line, and the three folder errors on Pick Source say what to do.

Close this dialog and fix the cause above. Tables listed as completed stay in the target; choose Skip for them if you import again.
NoteA run that stops on a failed table ends here instead of closing: the summary, one row per table, and a closing line that says what to do. Tables that completed stay in the target, so importing again with Skip for them avoids loading them twice. The failure wording is the driver's; the example above is a duplicate key. The same failure is reported once as a toast with “View in Audit”.

The other two Pick Source errors

No connection: the profile is not connected when the picker opens.
No active connection for this profileConnect to the profile, then open the import again.
No dialog: the platform offers no folder picker.
No folder picker available on this platformStart DBFlux in a desktop session that offers a file dialog, then try again.
NoteEach Pick Source error ends with what to do next, in the same error block as the file errors. “Invalid bundle” fires when a picked folder holds no manifest.json, or one this build cannot read; the next step points to Choose File… for a single file. The other two errors leave both buttons enabled once the cause is fixed.
