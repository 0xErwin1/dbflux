Import wizard: import a spreadsheet

Choosing a spreadsheet (.xlsx, .xlsm, .xls, .ods) in “Choose File…” adds one thing to Configure: a Sheet dropdown. One sheet is imported at a time; row 1 is the header. Every failure on this step names what is wrong and what to do next, and a disabled Continue says why in the footer.

NoteChoosing an .xlsx, .xlsm, .xls or .ods file in “Choose File…” lands on Configure. The Sheet row is new and comes first; it lists every sheet name in the workbook and starts on the first worksheet. The File line shows the workbook kind. One line says that row 1 is the header and that a spreadsheet has no delimiter or encoding options, in the same “why” style as the JSON line. Target table and the mapping card are the ones from the CSV flow (board 04).
NoteChoosing another sheet reads the file again at once, the way changing the encoding does for CSV, and the column mapping is rebuilt from the new sheet. Hidden sheets are left out of the list, and the Sheet hint says so, so a missing name is explained.
Keyboard↑ ↓ move in the open list, Enter chooses, Esc closes the list (a second Esc closes the wizard). Tab moves from the Sheet row to Target table.

Sheet “Registro” has 14,200,000 cells, over the limit of 10,000,000.The whole sheet is read into memory, so it cannot be imported. Export it as CSV from the spreadsheet app (Save as → CSV) and import the CSV instead, or pick a smaller sheet above.
Continue is off: the sheet is over 10,000,000 cells.
NoteAll four errors keep the file picked and stay on Configure. Each has two ways out: pick another sheet in the dropdown, or fix the file (or export a CSV) and choose it again. The danger block is the shared one from board 05: a circle-alert icon, the message, and a line that says what to do. The footer says why Continue is off. Each failed read is also reported once as a toast with “View in Audit”.
NoteThe limit is 10 million cells (rows × columns of the sheet range), counted before any row is read, so the wizard fails fast instead of freezing.
