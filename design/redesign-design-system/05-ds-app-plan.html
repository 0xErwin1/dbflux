App component plan

What each component in the code becomes: merged, restyled, extracted or new. Planned with the layout change, so each one is rebuilt once.

From today’s components to the new system

Built from an inventory of crates/dbflux_components, dbflux_ui_base and the shared chrome. The cut cannot be a radius token: every shape goes through the Chamfer primitive, so hand-rolled rounded divs only change once they move onto a component.

MergeFocusfocus_frame, form_navigation::focus_ringKeyboard focus only (focus-visible), never after a click. Single controls: tint ring, 1.5 px, following the cut; outside at 2 px on filled controls, inset otherwise. Composite controls (segmented, chips, tabs, lists) never ring the container: the focused item gets a tint underline or bar, or the row wash. Selection is fill only, so rings never nest.
