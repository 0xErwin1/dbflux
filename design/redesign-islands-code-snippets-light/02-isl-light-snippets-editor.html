Prefix completion, tabstop session states and the rules that start and end the session.

1 · Typing the prefix

The snippet is one more completion row. Its name reads like any other suggestion, the snippet name sits after it in the muted detail color, and the kind word “snippet” is right-aligned like table or cte. Rows keep today’s shape: no preview panel.

3a · After Tab

The user typed orders; field 2 (*) is now selected. Visited fields stay outlined. Shift+Tab goes back to the previous field.

2FROM orders

2 · After accepting (Enter or Tab)

The body is inserted, the first field is selected so typing replaces it, and the other fields get a dashed outline. Fields are visited by number (1 table, 2 *, 3 condition), not left to right. $0 is not drawn.

orders.sqlSQL
1SELECT *
2FROM table
3WHERE condition;

3b · Mirrored fields (cte snippet)

Repeating an index mirrors it: typing recent_orders in field 1 updates the second occurrence live, and both are outlined.

4 · Keys while a snippet is active

  • Tab moves to the next field and Shift Tab to the previous one; mirrors update as you type.
  • When the completion menu is open, Tab keeps cycling completions, as today (#1221). The next Tab after it closes moves to the next field.
  • Reaching the last field and pressing Tab lands on $0, where the cursor ends.

What ends the session

  • Esc ends it and keeps the inserted text.
  • Clicking outside the snippet ends it.
  • Reaching $0 ends it.
  • Editing outside the fields ends it. Typing inside a field does not.

Vim mode

  • Insert mode behaves exactly as above.
  • Switching to Normal mode ends the session; the text stays and the outlines disappear.
