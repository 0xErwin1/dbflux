Query error position: mark it, jump on request (#1030)

PostgreSQL, Redshift and SQLite report where in the query the error is. DBFlux marks that token with an editor diagnostic and offers Go to error; the cursor and focus never move on their own. Example: missing FROM-clause entry for table "c2".

1 · The run fails: the error is marked, nothing moves

The token the server points at is underlined, its line gets a mark in the gutter, and the cursor stays where the user was (end of line 1). The toast gains Go to error.

1-- Contacts without a match
2SELECT * FROM raw.contact c
3WHERE c2.contact_id IS NULL;
4
5SELECT count(*) FROM raw.contact;
!Query failed14:02:11
missing FROM-clause entry for table "c2" ERROR 42P01

2 · Go to error, on request

Clicking Go to error, or running Go to query error, moves the cursor to the marked token and focuses the editor. The marker stays until the next edit or run.

1-- Contacts without a match
2SELECT * FROM raw.contact c
3WHERE c2.contact_id IS NULL;
4
5SELECT count(*) FROM raw.contact;

3 · Pane actions and command palette

Go to query error sits in the pane actions menu and the palette, with no default key. It is enabled only while a marker exists (left: after a failed run; right: no marker).

4 · No position, no marker

A driver that reports no position, or a run whose sent text no longer matches the buffer (for example after an Influx time macro), shows the toast exactly as today: no underline, no Go to error.

1-- Contacts without a match
2SELECT * FROM raw.contact c
3WHERE c2.contact_id IS NULL;
4
5SELECT count(*) FROM raw.contact;
