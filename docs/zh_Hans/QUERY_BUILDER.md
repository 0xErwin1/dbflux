# 可视化查询构建器

对于 SQL 连接，无需编写 SQL 也能组合查询。在表的数据网格工具栏中点击 **构建器**，即可打开右侧栏面板。文档集合有自己的构建器，参见[文档集合](#文档集合)。

面板顶部有一个模式选择器 — **SELECT**、**UPDATE**、**DELETE** — 以及一个实时 SQL 预览，每次更改都会重新生成。预览始终可见。点击 **执行** 执行查询，或（在 SELECT 模式下）点击 **在编辑器中打开** 把生成的 SQL 放入普通查询编辑器。标题栏中有 **保存**、**重置**，以及一个关闭按钮：它会隐藏右侧栏并保留已构建的内容，点击 **Builder** 可再次显示。

| 按键                               | 操作                             |
|------------------------------------|----------------------------------|
| `Cmd+Enter` / `Ctrl+Enter`         | 执行                             |
| `Cmd+E` / `Ctrl+E`                 | 在编辑器中打开（仅 SELECT 模式） |
| `Cmd+S` / `Ctrl+S`                 | 保存                             |
| `Cmd+Shift+S` / `Ctrl+Shift+S`     | 文件另存为                       |
| `Cmd+Backspace` / `Ctrl+Backspace` | 重置                             |

## 构建 SELECT

SELECT 主体按从上到下的顺序分为以下几个部分：

- **列** — 投影，即要选取哪些列。
- **筛选** — 一个 `WHERE` 谓词树。谓词可以嵌套成 AND/OR 分组，因此可以可视化地组合复杂条件。
- **连接** — 附加的表，需要指定别名和 `ON` 条件。
- **按列分组 / 聚合项** — 见下文。
- **排序与限制** — `ORDER BY` 条目和分页边界。每个排序行由一个下拉菜单中选择的列（先是源表列，然后是被连接表的列）和一个 ASC/DESC 切换组成；第一行还包含限制值。最后一行用于添加另一个排序列，并包含偏移量。不支持排序的驱动只显示限制值和偏移量。

SQL 预览是参数化的：字面值会按当前活动方言（SQLite、PostgreSQL、MySQL/MariaDB 或 SQL Server）输出为占位符。

## GROUP BY 与聚合

在 **按列分组 / 聚合项** 部分添加分组列和聚合。支持的聚合函数为 `COUNT`、`COUNT(*)`、`COUNT(DISTINCT)`、`SUM`、`AVG`、`MIN` 和 `MAX`。每个聚合都有一个可编辑的别名，由函数和列名自动生成。

一旦查询进入分组状态：

- **列** 部分会替换为有效 `SELECT` 的只读预览（分组列在前，聚合别名在后）。
- 出现 **Having** 部分，使用与筛选相同的谓词编辑器，但作用于 `HAVING`。
- **排序** 下拉菜单只提供分组列和聚合别名。

分组结果在数据网格中的行为，参见[聚合结果](RESULTS.md#聚合结果)。

## Schema 感知自动补全

构建器的单行输入框（筛选、投影列、连接目标表，以及连接 `ON` 的两侧）提供内联建议，建议来源于实时 Schema 和构建器自身的 spec：源表列、已声明的连接别名，以及被连接表的列（在后台延迟加载）。输入 `<alias>.` 会把建议范围限定为该别名下的列。匹配仅按前缀进行。

| 按键                | 操作             |
|---------------------|------------------|
| `Up` / `Down`       | 在建议项之间移动 |
| `Tab` / `Enter`     | 采用高亮的建议项 |
| `Esc`（或失去焦点） | 关闭建议         |

数据网格的 `WHERE` 筛选输入框也提供同样的自动补全（参见[筛选结果](RESULTS.md#筛选结果)）。

## 已保存的查询

构建器可以按连接配置保存，之后重新打开。已保存的查询归属于该连接配置，名称唯一。已保存的查询也可以导入到另一个连接上；导入时，DBFlux 会先验证被引用的表在目标连接上存在，再加载。

## 可视化 UPDATE 与 DELETE

把模式选择器切换到 **UPDATE** 或 **DELETE** 即可构建变更语句。两种模式都复用同一个筛选编辑器来构造 `WHERE` 子句；UPDATE 额外提供一个赋值部分，用于 `SET` 列（包括原生 SQL 表达式赋值）。SQL 预览全程保持可见。

变更受一项策略约束，该策略综合了连接的只读状态与执行者上下文：

| 策略     | 效果                                 |
|----------|--------------------------------------|
| 允许     | 可以执行该变更。                     |
| 只读     | 不允许执行变更（例如只读连接配置）。 |
| 需要审批 | 该变更必须先获得审批才能执行。       |

**执行模式。** **执行** 部分提供三种模式，默认值根据行数估计、驱动的事务支持能力和主键可用性自动建议。覆盖该建议时会弹出一个权衡说明模态框。

| 模式         | 行为                                                                                                                                                                                |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **单事务**   | 整个变更使用一个事务。                                                                                                                                                              |
| **分块事务** | 基于表的主键以 keyset 方式分页，把变更拆分成多个分块（分块大小限制在 `[1000, 10000]`，默认 5000）。每个分块各自是一个事务，会在任务面板中显示条目，支持在分块之间取消，失败时回滚。 |
| **直接**     | 不使用事务包装（自动提交）。在驱动不支持事务时使用。                                                                                                                                |

**危险查询闸门。** 不带 `WHERE` 的 `UPDATE` 或 `DELETE` 在执行前会受到危险查询确认的拦截（参见[危险查询确认](EDITOR.md#危险查询确认)）。

## 键盘

在表格的网格中按 `Ctrl+l` 可将键盘移入构建器。`j` 和 `k` 在各行之间移动光标，`h` 和 `l` 在一行的字段之间移动，`Enter` 操作该字段：在文本框中输入、打开下拉列表或按下按钮。`a` 添加一项，`Shift+a` 添加筛选分组，`x` 删除该行，`Space` 切换其开关。`Alt+l` 和 `Alt+h` 切换模式，`m` 打开包含执行、保存、重置等操作的菜单，`Escape` 或 `Ctrl+h` 返回表格。完整列表见[查询构建器](KEYBOARD.md#查询构建器)。

## 文档集合

支持该功能的驱动（MongoDB）上的集合提供一个可视化构建器，用于构建 find 查询和简单聚合。点击集合标题栏中的 **构建器** 即可在右侧栏中打开它；再次点击或点击右侧栏的关闭按钮即可隐藏。标签页打开期间，草稿会一直保留。在没有构建器的文档驱动（例如 DynamoDB）上，该按钮处于禁用状态，其提示说明原因；查询栏位仍可正常使用。

右侧栏包含 **Find** / **Aggregate** 模式切换、下文介绍的各个卡片，以及固定在页脚上方、使用驱动自身语法的查询预览。页脚用于运行查询（Find 模式下为 **查找**，Aggregate 模式下为 **运行管道**），或将预览在查询编辑器中打开（**在编辑器中打开**）。

### Find 模式

| 卡片 | 构建内容 |
|------|----------|
| **筛选** | 以 *全部满足*（`$and`）或 *任一满足*（`$or`）组合的条件，支持嵌套分组。 |
| **投影** | 要包含或排除的字段。`_id` 始终返回，因此结果行保持可编辑。 |
| **排序、限制与跳过** | 排序键（各自升序或降序），然后是限制值和跳过值。 |

每个条件由字段、运算符和值组成。提供的运算符取决于该字段在 Schema 样本中的类型，范围为 `$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`、`$regex`、`$exists`、`$elemMatch`、`$size` 和 `$all`。样本中包含多种类型的字段会被标记，其条件提供每种类型的运算符。值的输入方式取决于运算符：

| 运算符或类型 | 值输入方式 |
|--------------|------------|
| `$in`、`$nin`、`$all` | 值列表，每个值一个标签（输入值后按 `Enter`）。 |
| `$exists`，以及布尔字段上的 `$eq` / `$ne` | true / false 开关。 |
| `$regex` | 模式，`/pattern/flags` 或不带分隔符的模式。 |
| `$size` | 元素个数（整数）。 |
| `$elemMatch` | 数组中某个元素必须满足的条件。 |
| 日期字段 | `YYYY-MM-DD`、`YYYY-MM-DD HH:MM`（UTC）或 RFC 3339 时间戳。 |
| ObjectId 字段 | 24 位十六进制数字。 |

字段通过一个选择器选取，其数据来自结构视图的样本：嵌套路径、每个路径的类型标记以及该字段的出现率。样本中未出现的路径可以直接输入并按 `Enter` 使用；它会被标记为未采样。

**查找** 通过查询栏运行查询，与栏位的运行方式相同：结果是普通文档，可编辑、会计数，并记入查询历史。

### 与查询栏同步

右侧栏打开期间，构建器与 `filter`、`project`、`sort` 和 `limit` 栏位双向同步：在构建器中编辑会重写其更改的栏位，在栏位中编辑会重新加载构建器，并丢弃尚未完成的条件。右侧栏关闭期间或构建器处于 Aggregate 模式期间更改的栏位，会在右侧栏重新打开或构建器返回 Find 时重新读取：构建器在此期间未更改的部分采用栏位中的查询。从历史记录运行查询也会重新加载构建器并清除其跳过值。

跳过值没有对应的栏位；它在右侧栏打开期间生效，分页从它开始计数：向前翻页会停在跳过值处，更改每页大小后会从那里重新开始。

当某个栏位包含构建器无法显示的子句（例如 `$expr`）时，构建器会显示它能理解的部分，将其余部分设为只读，并显示一张带有两个选项的卡片。会更改该栏位的构建器编辑会等待你做出选择，有编辑等待期间 **查找** 处于禁用状态。没有等待中的编辑时，**查找** 按栏位中已写的内容运行。

| 选项 | 效果 |
|------|------|
| **保留文本** | 丢弃等待中的构建器编辑，保留栏位中已写的内容。 |
| **从构建器重写** | 用构建器的查询替换各栏位，丢弃其无法显示的子句。 |

### Aggregate 模式

在 **分组** 卡片中添加分组阶段会切换到 **Aggregate**，移除分组阶段则返回 **Find**。Aggregate 模式需要能够运行聚合管道的驱动。

- **分组依据** 可以包含零个或多个字段；不指定字段时，所有文档构成一个分组。
- **累加器** 为 `$count`、`$sum` 和 `$avg`，每个都有一个输出名称。`$sum` 和 `$avg` 需要一个数值字段。
- 筛选条件会成为 `$match` 阶段，并以摘要形式显示，附带 **编辑** 按钮。
- 不使用 **投影**：输出字段为分组键和累加器。
- 排序键只能是分组键或累加器。

**运行管道** 会把管道写入集合的聚合视图并在那里运行。分组行是计算得出的，因此没有可编辑的 `_id`：结果为只读，并带有一条说明此情况的提示。构建器处于 Aggregate 模式时，查询栏和聚合视图显示管道摘要，而不是栏位和管道编辑器。聚合视图正在运行管道或等待确认时，**运行管道** 不会改动它，并提示没有运行任何内容。

### 已保存的文档查询

在右侧栏标题中为查询命名，然后点击 **保存查询**。已保存的查询归属于该集合：其连接配置、数据库和集合名称。使用已存在的名称保存会替换该查询。**已保存的查询** 会列出它们；打开其中一个时，会以保存时的模式加载。打开已保存的 find 会替换全部四个栏位，包括构建器无法显示的子句。

### 限制

- 由 24 位十六进制数字组成的文本值会作为 ObjectId 运行，因为驱动会转换此类字符串。构建器要求将其作为 ObjectId 输入，因此无法将包含此类字符串的文本字段作为文本搜索。
- 小数值按 double 比较，因此不会匹配 `Decimal128` 字段。
- 在栏位中，`{"$date": "..."}` 只接受 RFC 3339 时间戳，例如 `2024-03-09T14:30:05Z`。
- 构建器不支持写入阶段（`$out`、`$merge`），也不构建更新或删除操作。
- 删除已保存的查询时不会要求确认。
