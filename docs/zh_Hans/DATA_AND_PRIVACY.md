# 数据与隐私

DBFlux 把数据存放在哪里、如何保护你的凭据、审计日志保留哪些内容，以及如何备份或彻底重置。

## 速览

| 你的数据 | 存放位置 |
|---|---|
| 连接配置、设置、历史记录、已保存的图表/查询、审计日志 | 一个 SQLite 文件：数据目录下的 `dbflux.db` |
| 已打开的标签页 / 会话 | 同一个 `dbflux.db`，外加数据目录中的临时文件 |
| 密码、口令、API 密钥 | 你的**操作系统密钥环** —— 绝不在 `dbflux.db` 中 |
| IPC/MCP 认证令牌 | 配置目录中的一个 `0600` 文件 |

DBFlux 几乎把所有内容都放在同一个 SQLite 数据库中。密钥是刻意的例外：它们交给操作系统的密钥环保存，数据库里只存一个指向它们的*引用*。

---

## 数据位置

DBFlux 使用各平台的标准目录。

| 平台 | 数据目录 | 配置目录 |
|---|---|---|
| **Linux** | `~/.local/share/dbflux/` | `~/.config/dbflux/` |
| **macOS** | `~/Library/Application Support/dbflux/` | `~/Library/Application Support/dbflux/` |
| **Windows** | `%APPDATA%\dbflux\` | `%APPDATA%\dbflux\` |

数据目录中包含：

- **`dbflux.db`** —— 统一的数据库（即下文[数据库里有什么](#数据库里有什么)中列出的全部内容）。
- **`st_sessions/`** —— 已打开的编辑器标签页所对应的临时文件（影子文件）。
- **`ipc_auth_token`** —— IPC/MCP 认证令牌（参见[下文](#ipcmcp-认证令牌)）。
- **`ssh_known_hosts`** —— 已接受的 SSH 主机密钥（TOFU，首次使用即信任）。

DBFlux 已不再使用配置目录。旧版本会把 IPC 认证令牌和 SSH 已知主机存放在那里；升级后可能仍有残留文件，可以直接删除。

### stable 与 nightly 的区别

nightly 构建使用独立的数据库文件 `dbflux-nightly.db`，因此预发布版本的迁移永远不会触及你的 stable 数据。stable 与 rc 构建版本都使用 `dbflux.db`。

你也可以让 nightly 构建共用 stable 数据库：在**设置 > 常规 > 存储 > 使用稳定数据库**中开启（下次启动时生效）。其内部实现只是在数据目录中放一个空的 `use-stable-db` 标记文件。

## 数据库里有什么

`dbflux.db` 是一个单独的 SQLite 文件。它的表按前缀分组：

| 前缀 | 包含内容 |
|---|---|
| `cfg_*` | 配置：连接配置、认证/代理/SSH 隧道配置、RPC 服务、连接 Hook、MCP 治理，以及常规/审计设置。（密钥的*值* **不在**这里 —— 这里只有密钥环引用。） |
| `st_*` | 工作台状态：已打开的会话/标签页、**查询历史**（完整的查询文本）、已保存的查询、最近使用项、Schema 缓存、界面状态。 |
| `aud_*` | 审计日志与已保存的审计筛选条件。 |
| `viz_*` | 已保存的图表与仪表盘。 |
| `qry_*` | 可视化查询构建器中保存的查询。 |
| `sys_*` | 内部数据：Schema 迁移版本、应用元数据。 |

> **关于查询历史的说明。** 工作台的查询历史（`st_*`）以**明文**保存你所执行查询的**完整文本**。这与审计日志是两套不同的存储 —— 后者默认只对查询文本做指纹处理（见下文）。如果你不希望保留查询文本，请在设置 > 常规中调低**最大历史条目数**，或在编辑器的历史视图中清除历史记录。

## 密钥与操作系统密钥环

密码、SSH 口令、代理凭据和提供程序密钥都存放在操作系统的密钥环中，**而不是** `dbflux.db` 里。

| 平台 | 密钥环后端 |
|---|---|
| **Linux** | Secret Service（GNOME Keyring / KWallet，经由 libsecret） |
| **macOS** | Keychain（钥匙串） |
| **Windows** | Windows 凭据管理器 |

所有条目都存放在服务名 **`dbflux`** 之下。数据库中每个密钥只保存一个引用字符串：

| 密钥 | 引用 |
|---|---|
| 连接密码 | `dbflux:conn:<profile-id>` |
| 内联的 SSH 密码/口令 | `dbflux:ssh:<profile-id>` |
| 已保存的 SSH 隧道 | `dbflux:ssh_tunnel:<tunnel-id>` |
| 代理凭据 | `dbflux:proxy:<proxy-id>` |
| 认证配置文件的字段 | `dbflux:auth:<profile-id>:<field>`（每个字段一条） |

### 密钥何时会被保存（何时不会）

- 连接密码只有在你勾选**保存密码**时才会被保存；SSH 与代理的密钥则只在勾选各自的**保存**复选框时才会保存。
- 如果没有可用的密钥环，DBFlux 会隐藏**保存**复选框，并且不会持久化任何密钥 —— 你需要在每次会话中重新输入。
- **已锁定**的密钥环仍然算作可用：在你解锁之前写入可能会失败，但 DBFlux 会继续保持密钥支持处于启用状态。

## 会话与标签页恢复

你打开了哪些标签页 —— 它们的类型、文件路径、顺序、当前激活的标签页以及固定状态 —— 都记录在 `dbflux.db` 中（`st_sessions` / `st_session_tabs`）。而实际的临时/影子文件内容则与它并列存放在数据目录的 `st_sessions/` 下。启动时，如果**设置 > 常规 > 启动时恢复会话**处于开启状态（默认开启），DBFlux 就会恢复这个会话。

## 审计与隐私

DBFlux 会把重要操作（查询、连接、Hook、脚本、配置变更、MCP/治理决策）记录到 `dbflux.db` 中的审计日志。它在设计上默认就是保护隐私的：

| 行为 | 默认值 | 效果 |
|---|---|---|
| **捕获查询文本** | 关闭 | 查询文本会被替换为一个 SHA-256 **指纹**及其长度 —— 完整文本永远不会存入审计记录。 |
| **脱敏敏感值** | 开启 | 敏感模式（AWS 密钥、JWT、带凭据的连接字符串等）会被替换为 `[REDACTED]`。 |
| **详情大小上限** | 64 KiB | 过大的事件载荷会被截断为一个只包含部分内容的小消息信封。 |

敏感的 **JSON 键**（`password`、`token`、`secret`、`api_key`、`access_key`、`session_token`、`connection_string`、`url` 等）始终会被脱敏 —— 即使你关闭了基于模式的脱敏。

> 请记住上文[关于查询历史的说明](#数据库里有什么)：审计日志只对查询文本做指纹处理，而*工作台历史*保存的是完整文本。它们是两个不同的存储。

完整的事件结构、类别与查看器，参见[审计](AUDIT.md)以及[仪表盘与审计 → 审计查看器](DASHBOARDS_AND_AUDIT.md#audit-viewer)。

## IPC/MCP 认证令牌

DBFlux 对外暴露一个本地 IPC 接口（供 MCP 服务器与外部 RPC 服务使用）。它用一个令牌来认证调用方，该令牌存放在：

```
<data dir>/dbflux/ipc_auth_token
```

（在 Linux 上为 `~/.local/share/dbflux/ipc_auth_token`）。它是一个随机值，每次启动时重新生成，以仅所有者可读的 `0600` 权限写入，同时也会导出到 `DBFLUX_IPC_TOKEN`、`DBFLUX_DRIVER_IPC_TOKEN` 和 `DBFLUX_AUTH_PROVIDER_IPC_TOKEN` 三个环境变量，供子进程使用。

这个令牌**只代表进程身份** —— 任何能读到它的本地进程都可以连接。在没有额外认证层的情况下，不要把 IPC/MCP 接口暴露到 localhost 之外。信任模型参见 [AI + MCP 集成](MCP_AI_INTEGRATION.md)。

## 备份与重置

DBFlux 没有专门的备份/恢复命令，但由于所有内容都在同一个文件里，这两件事都很直接。

### 备份

在 DBFlux 关闭的情况下，复制这一个数据库文件即可：

```
~/.local/share/dbflux/dbflux.db        # Linux（其他平台请相应调整）
```

这个文件包含你的连接配置、历史记录、已保存的图表/查询和审计日志。你的**密钥不在其中** —— 它们留在操作系统密钥环里 —— 所以把数据库复制到另一台机器后，它会引用那台机器上并不存在的密钥环条目，直到你重新输入这些密钥。

### 彻底重置

要清除 DBFlux 的数据：

1. 删除**数据目录**（Linux 上为 `~/.local/share/dbflux/`）—— 这会移除数据库、会话文件、IPC 认证令牌和 SSH 已知主机。
2. **仅旧版本需要：** 如果旧版的配置目录（Linux 上为 `~/.config/dbflux/`）仍然存在，一并删除 —— 当前版本已不再使用它。
3. **手动清除密钥环条目。** 删除目录后，服务名为 `dbflux` 的密钥仍会留在你的操作系统密钥环中；如果你想要彻底清除，请用所在平台的密钥环工具把它们删掉。

> 删除数据目录是不可撤销的操作。如果你还可能需要找回连接配置或历史记录，请先备份 `dbflux.db`。
