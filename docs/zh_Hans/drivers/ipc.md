# 外部 RPC 驱动程序

一座桥梁，让运行在自己进程中的驱动程序通过本地 Socket 为 DBFlux 提供服务，从而可以在不分叉应用程序的前提下，接入 DBFlux 本身不支持的数据库。

## 速览

- **类别** —— 由远端驱动程序声明
- **查询语言** —— 由远端驱动程序声明
- **注册 ID** —— `rpc:<socket_id>`
- **协议** —— 参见驱动程序 RPC 协议参考

## 工作原理

这座桥梁本身不掌握任何具体数据库的知识。连接时，它会与远端进程执行一次 `Hello` 握手；DBFlux 呈现该驱动程序所需的全部信息 —— 它的类型、元数据、连接表单 —— 都在这份回复中返回。此后，桥接层通过 Socket 转发各项操作，并把响应翻译成内置 Rust 驱动程序所实现的同一套核心契约，因此应用程序的其余部分无法察觉其中的差别。

连接取值以 `DbConfig::External { kind, values }` 的形式持久化，键由远端驱动程序所声明的表单决定。

### 握手时协商的能力

远端驱动程序声明自己支持什么，桥接层据此适配：

- `SchemaIntrospection` —— 侧边栏据此构建 Schema 树
- `MultiDatabase` —— 该连接对外暴露多个数据库
- `ChunkedResults` —— 大型结果集以分块方式流式返回，而不是一次性返回
- `Cancellation` —— 正在运行的查询可以从界面取消
- `AuditEmit` —— 驱动程序可以发出自己的审计事件（协议 v1.2 及以上）

未声明的能力在界面上就直接不存在，这与内置驱动程序未设置的能力标志把相应特性从界面移除是同一个道理。

### 宿主进程生命周期

已配置的 RPC 服务可以由 DBFlux 托管：宿主进程按需启动，等待其报告健康状态，并被跟踪以便关闭。没有启动配置的服务则被假定为已经在运行。

### 审计转发

声明了 `AuditEmit` 的驱动程序可以发送与自身响应交错的 `EmitAuditEvent` 帧。桥接层会拦截这些帧，并把它们分派给宿主的净化接收端（sink），因此外部驱动程序的事件会与其他所有事件一样落入同一份审计日志，并经过同样的脱敏处理。来自未声明该能力的驱动程序的帧会被丢弃，而不是被信任。

## 限制

- 需要一个兼容的驱动程序宿主进程以及可访问的 Socket。桥接层无法启动没有启动配置的宿主，因此不可用的服务就始终不可用。
- 实际的功能集受限于远端驱动程序声明的元数据及其实现。桥接层绝不会添加驱动程序本身不具备的能力。
- 审计事件的发出需要协议 v1.2 及以上，并且在握手时包含 `AuditEmit`。旧版驱动程序不发出任何审计事件，它们的操作只会通过 DBFlux 代为记录的事件出现在日志中。
