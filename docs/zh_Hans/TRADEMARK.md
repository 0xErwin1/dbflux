# DBFlux 商标政策

DBFlux 的源代码是采用 `MIT OR Apache-2.0` 许可的自由软件。但 **DBFlux** 这一名称、DBFlux 标识，以及 `dbflux.dev` 域名并不在该授权范围内。本文档说明在无需另行询问的前提下，你可以如何使用它们。

## 快速了解

1. 你可以用这个名称说明自己作品的来源：「基于 DBFlux」「DBFlux 的一个分叉」「与 DBFlux 兼容」。
2. 你可以以 DBFlux 之名再分发**未经修改**的官方发布制品，例如做成 Homebrew、AUR 或 nixpkgs 软件包。
3. 如果你发布的是**修改过的**构建版本，请使用不同的名称与标识，并说明你的项目衍生自 DBFlux，并非官方版本。

如果你的情况不属于以上三种，请在本仓库提交 issue 询问。

## 涵盖的标识

| 标识 | 含义 |
|------|---------------|
| DBFlux | 产品名称，不限大小写，单独使用或用于复合名称（如 "DBFlux Pro"、"DBFlux Nightly"）均可。 |
| 标识 | `resources/branding/` 与 `packaging/icons/` 下的每一个文件，以及它们的任何衍生作品。 |
| dbflux.dev | 该域名及其下的每一个页面。 |

代码许可并不改变这一点。Apache 2.0 文本在第 6 节中已明确说明。MIT 则完全未提及商标，因此选择 MIT 而非 Apache，并不会授予 Apache 所保留的那些名称权利。

## 可以做与不可以做

| 用途 | 无需询问即可使用 |
|-----|------------------------|
| 说明来源、兼容性或对比关系（「基于 DBFlux 构建」「可与 DBFlux 配合使用」） | 可以 |
| 在分叉项目的源文件、提交历史与文档中保留该名称 | 可以 |
| 以 DBFlux 之名打包或镜像**未经修改**的官方发布版本 | 可以 |
| 撰写关于 DBFlux 的文章、演讲或教程，包括在截图中出现标识 | 可以 |
| 为包含官方发布版本之外补丁的构建版本使用其名称与标识 | 不可以 |
| 从其他仓库发布以 DBFlux 为品牌的发布版本、安装程序或更新渠道 | 不可以 |
| 注册以 "DBFlux" 为主要构成部分的域名、包名、应用商店条目或账号 | 不可以 |
| 将标识（或其修改版本）用作衍生产品的图标 | 不可以 |

「未经修改」指该制品由本仓库某个标签经官方发布工作流生成，且其校验和与随该版本发布的校验和一致。若从同一标签重新构建，且源代码树与该标签逐字节一致，也视为「未经修改」。

## 为分叉项目命名

衍生产品需要一个不会让用户与 DBFlux 混淆的名称。以下做法是可行的：

- 使用带有来源说明的独特名称：例如「Fluxbase，DBFlux 的一个分叉」。
- 加上能清楚表明非官方身份的限定语：在 README 中写「DBFlux（社区版，非官方）」是可以接受的，但二进制文件、窗口标题、包标识符与安装程序不得把自己呈现为纯粹的 "DBFlux"。

以下做法则不可行：

- 从分叉项目发布名为 "DBFlux vX.Y.Z" 的版本。
- 在应用仍自称 DBFlux 的情况下，把应用内的更新检查指向某个分叉项目。
- 把 DBFlux 图标，或改色后的版本，当作应用图标重复使用。

更名并不一定要改动源代码树。修改显示名称、包标识符、图标集、`repository` 字段与发布标题就已足够。

## 为何有此政策

安装 "DBFlux" 的用户，期待的是本项目发布的构建版本：经过评审的改动、有文档记载的数据与隐私行为，以及在平台支持时进行签名的制品。以同一名称发布经过修改的构建版本会打破这一预期，而由此产生的缺陷报告最终会落到本项目。
