# 设置与连接 Hooks

DBFlux 各设置项以及连接 Hooks 的参考说明——连接 Hooks 指在连接生命周期前后由 DBFlux 执行的命令、脚本或 Lua 代码片段。

可通过命令面板（**Open settings**）或侧边栏打开“设置”。该窗口左侧按设置项纵向排列。

| 设置项 | 内容 |
|---------|--------|
| [常规](#常规) | 应用程序级行为：主题、启动、刷新、查询安全。 |
| [审计](#审计) | 审计日志记录的内容与保留时长。 |
| [键盘快捷键](#键盘快捷键) | 浏览和修改键位映射。 |
| [认证配置文件](#认证配置文件代理与-ssh-隧道) | AWS SSO / 共享凭证配置文件。 |
| [代理](#认证配置文件代理与-ssh-隧道) | SOCKS5 / HTTP 代理配置文件。 |
| [SSH 隧道](#认证配置文件代理与-ssh-隧道) | 可复用的 SSH 隧道配置文件。 |
| [RPC 服务](#rpc-服务) | 外部 RPC 驱动与认证提供程序。 |
| [Hooks](#连接-hooks) | 可复用的连接 Hook 定义。 |
| [驱动](#驱动) | 各驱动的覆盖项与设置。 |
| 关于 | 版本与构建信息。 |

与 MCP 相关的设置项（客户端、角色、策略）仅在二进制文件以 `mcp` 特性构建时显示（默认即带有该特性）；参见[AI + MCP 集成](MCP_AI_INTEGRATION.md)。

### 外观

| 设置项 | 选项 | 默认值 |
|---------|---------|---------|
| **主题** | 跟随系统、深色、浅色 | 深色 |

| **语言** | 跟随系统，其后为所有附带翻译目录的语言 | 跟随系统 |
| **界面字体** | 默认（Archivo），或任意已安装字体 | 默认 |
| **界面字号** | 8 到 32 px，可用小数 | 13 |
| **编辑器字体** | 默认（JetBrains Mono），或任意已安装字体 | 默认 |
| **编辑器字号** | 8 到 32 px，可用小数 | 13 |
| **数据表格字体** | 与编辑器相同，或任意已安装字体 | 与编辑器相同 |
| **数据表格字号** | 8 到 32 px，可用小数 | 12.5 |

字体更改在保存后立即应用到所有已打开的窗口，无需重启。编辑器字体同时决定界面中的等宽文字（元数据、快捷键提示、控制台），自定义的界面字体也会替换分区标签使用的加宽展示字体。各字号控制的内容：

- **界面字号**：缩放界面中的所有文字、行、控件和图标。
- **编辑器字号**：决定代码编辑器的文字与行高，以及控制台文字。
- **数据表格字号**：决定单元格文字、行高与表头高度，以及自动列宽。手动调整过宽度的列保持原宽度。

由于系统中可能有数百种字体，字体列表提供搜索框。已保存但不再安装的字体仍保持选中，并标注“（未安装）”；在重新安装之前，DBFlux 使用默认字体绘制，数据表格则回退为编辑器字体。

语言列表来自 DBFlux 附带的翻译目录：英文排在最前，其余语言按固定顺序排列，并以各自语言中的名称显示。选择“跟随系统”时以操作系统的区域设置为准；若没有明确匹配的附带区域设置，则回退为英文。语言更改将在重启 DBFlux 后生效，因此该控件会始终显示这一提示。不完整的翻译目录对未翻译的通用界面文本回退显示英文。本版本仅翻译了「常规」设置项；界面其余部分正按 crate 逐个转换，目前仍为英文。

### 执行安全（危险查询确认）

以下三项设置决定 DBFlux 如何处理**所有**驱动与查询语言中的危险查询。没有按数据库区分的开关——同一套规则适用于 SQL 的 `DELETE`/`DROP`/`TRUNCATE`、MongoDB 的 `deleteMany`/`drop`、Redis 的 `FLUSHALL`/`FLUSHDB` 等。

| 设置项 | 作用 |
|---------|--------------|
| **确认危险查询** | 默认开启；执行危险查询前显示确认对话框。关闭后将不再提示而直接执行。 |
| **DELETE / UPDATE 需要 WHERE** | 默认开启；不带 `WHERE` 的 `DELETE`/`UPDATE` 被视为危险查询。 |
| **始终要求预览（忽略抑制）** | 默认关闭；即使此前选择不再确认的查询，也强制弹出确认/预览对话框。 |

**编辑器行数上限**（默认 10,000）限制从查询编辑器运行的查询返回的行数。它是独立于上述三项危险查询设置的执行安全选项。它只接受大于等于 1 的整数，不能设为零或关闭：保存其他值会显示错误并保留之前的上限。DBFlux 随每个编辑器查询把上限传给驱动，而不是在查询文本中加入 `LIMIT`，并在结果省略了行时显示警告。在包含多条语句的脚本中，所有结果集共享同一个上限，每条语句仍会执行。

无法执行行数上限的驱动会在运行前拒绝查询，而不是忽略上限。因此在 MongoDB、Redis、Turso、InfluxDB、ClickHouse、Redshift、CloudWatch、外部 RPC 驱动以及 DynamoDB 写操作（PartiQL `INSERT`/`UPDATE`/`DELETE` 和 put、update、delete 命令）上，编辑器查询会以 "Operation not supported" 错误失败。修改上限不会改变这一点。此上限不会增加超时，也不适用于 Lua、Python 或 Bash 脚本、连接钩子或指标。[控制台](CONSOLE.md)会把同一上限发送给能够执行它的驱动，在其他驱动上则不带上限运行命令。

## 审计

「审计」设置项控制统一的审计日志。面向用户的主要控件是 **日志捕获 → 最低日志级别**（跟踪 / 调试 / 信息 / 警告 / 错误），用于设定将 DBFlux 内部日志中的多少内容纳入审计记录。保存后无需重启即可生效。

保留期（事件保留时长）在配置后会驱动周期性的后台清理。日常使用审计功能（打开查看器、筛选、导出）参见[审计 → 审计查看器](AUDIT.md#审计查看器)。完整的事件结构与脱敏行为参见[审计](AUDIT.md)与[数据与隐私](PRIVACY.md#审计与隐私)。

## 键盘快捷键

本设置项按上下文分组列出当前生效的键位映射。可用文本框按命令、按键或上下文谓词筛选，或用上下文筛选只显示一个上下文。继承自其他上下文的上下文（编辑器继承自全局）还会列出它未覆盖的继承绑定。完整的默认键位映射记录在[键盘快捷键](KEYBOARD.md)。

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="../images/settings/keybindings-dark.webp">
  <img src="../images/settings/keybindings-light.webp" alt="设置窗口的键盘快捷键部分，列出全局快捷键，每项都带有用于修改的铅笔按钮">
</picture>

**修改快捷键。** 点击某个绑定的铅笔，或选中它后按 `Enter`，然后按下新的按键。快捷键可以是一个带修饰键的按键，也可以是最多四个按键组成的序列，例如 `g g` 或 `Ctrl+K Ctrl+S`：依次按下它们，停顿一秒后录制即会保存。`Esc` 取消。录制时，**移除快捷键**会让该绑定不再有按键。设置窗口自身使用的按键（如 `Ctrl+S` 或 `Tab`）也可以录制。单独的 `Esc` 因用于取消而无法录制。

**上下文。** 每个绑定都在一个上下文中生效，上下文用与 Zed 相同的谓词语言书写。点击绑定的图层按钮，或选中它后按 `p` 进行编辑；`Enter` 保存，`Esc` 取消。谓词用 `&&`、`||` 和 `!` 组合名称，用 `==` 或 `!=` 比较取值，用 `A > B` 表示"位于 A 之内的 B"，并可用括号分组：

| 谓词 | 生效范围 |
|------|----------|
| `Editor && !Modal` | 在代码编辑器中，且没有打开对话框时 |
| `Editor && vim_mode == normal` | 在处于 Vim 普通模式的代码编辑器中 |
| `Editor && language == mongo` | 在编写 MongoDB 查询的代码编辑器中 |
| `Results \|\| Audit` | 在结果表格或审计查看器中 |
| `SidebarPanel && tab == scripts` | 在侧边栏的脚本标签页中 |
| `CodeEditor > Input` | 在代码编辑器的文本缓冲区中 |

可用的名称包括上下文筛选中显示的上下文名称（`Global`、`Sidebar`、`Editor`、`Results`、`DataTable`、`Input`、`Modal`……）、窗口名称 `Workspace`、`SettingsWindow` 和 `ConnectionManagerWindow`，以及面板名称 `ActivityRail`、`CommandSearch`、`SidebarPanel`、`CodeEditor`、`ResultPanel`、`RowInspector`、`KeyValueConsole`、`NativeConsole`、`DocumentQueryBar`、`DocumentSchema`、`DocumentAggregate`、`DashboardsPanel` 和 `SettingsSection`。可用的取值有 `vim_mode`（`normal`、`insert`、`replace`、`visual`、`visual_line`、`visual_block`，仅在开启 Vim 编辑时存在）、`language`（`sql`、`mongo`、`redis`、`lua`、`python`、`bash`……）、`tab`、`section` 和 `focus`。无法解析的谓词不会保存；引用了 DBFlux 从不设置的名称的谓词会带着警告保存，因为它永远不会匹配。

**哪个绑定优先。** 拥有焦点的元素（文本框、数据表格、对话框、文档树）的绑定优先于包围它的面板的绑定，你修改过的绑定优先于同一位置绑定到相同按键的默认绑定。开启 Vim 编辑时，你为某个 Vim 模式创建的绑定（例如 `Editor && vim_mode == normal` 中的 `space r`）会在 Vim 读取按键之前执行；默认绑定则把 Vim 自己的按键留给 Vim。拥有焦点的按钮、复选框或列表行总是自己处理 `Enter` 和 `Space`。

**警告与冲突。** 如果新按键已被一个可能同时生效的上下文中的其他命令使用，此时不会保存任何内容：警告会列出另一个命令及其上下文。**取消**保持原样。**替换**会把按键分配给正在编辑的绑定，并从另一个绑定上移除，后者在你恢复它之前没有快捷键。与其他绑定冲突的绑定会显示"与……冲突"标记，页脚会统计冲突数量。另有两个标记只提示、不阻止保存："共用按键序列"表示一个绑定的按键是另一个绑定按键的开头（此时 DBFlux 会在较短的按键之后等待一秒，看较长的是否接着输入）；"会拦截输入的文字"表示在输入文字的地方（例如文本框，或处于 Vim 普通与可视模式之外的代码编辑器）绑定了不带修饰键的字母。

**恢复默认。** 已修改的绑定会显示一个恢复箭头，用于恢复其默认按键和上下文（在选中的绑定上按 `r` 效果相同，按 `Delete` 则移除其快捷键）。页脚中的**全部恢复默认**会丢弃所有修改，在列表中按 `Shift+R` 效果相同。按 `c` 打开上下文筛选。页脚还会显示已修改的绑定数量。

修改会立即在所有窗口中生效，无需重启。只保存你的修改，存放在 `dbflux.db` 的 `cfg_keybinding_overrides` 表中，因此未修改的绑定会跟随后续版本的默认值。如果后续版本移除了某项修改所对应的默认绑定，该修改会被忽略。

## RPC 服务

外部驱动与认证提供程序以独立进程运行，DBFlux 通过本地 Socket 与之通信。在此添加的每项服务包含：

| 字段 | 说明 |
|-------|-------|
| **Socket ID** | 唯一标识，用作 Socket 文件名。仅允许 ASCII 字母、数字、`.`、`_`、`-`。 |
| **命令** | 要启动的可执行文件（某些配置下可省略）。 |
| **启动超时（ms）** | 等待进程启动的时长。默认 5000。 |
| **服务类型** | **驱动**或**认证提供程序**。 |
| **启用此服务** | 是否启动该服务。默认开启。 |
| **参数** | 按顺序排列的进程参数。 |
| **环境变量** | 传递给进程的 `KEY=value` 键值对。 |

此处的更改**在下次启动时生效**。完整参考：[RPC 服务配置](RPC_SERVICES_CONFIG.md)与[驱动 RPC 协议](DRIVER_RPC_PROTOCOL.md)。

## 驱动

选择一个驱动即可查看并覆盖其行为。有两组内容可编辑：

**全局覆盖** —— 各驱动对应的「常规」设置版本。每一项都是三态（继承 / 开 / 关，或一个显式值）；保持为*继承*时，将使用控件旁显示的「常规」默认值：

- 刷新策略与间隔
- 确认危险查询
- 需要 WHERE
- 需要预览

**驱动设置** —— 由驱动自身定义的选项（根据驱动自带的 schema 通用渲染，因此可用字段取决于驱动）。

该设置项还以只读方式显示驱动的能力矩阵、类别与查询语言。

## 连接 Hooks

Hooks 是在连接生命周期前后执行的可复用命令、脚本或 Lua 代码片段。你在**设置 → Hooks** 中全局**定义**它们，然后在连接管理器的 **Hooks** 标签页中将它们**绑定**到各连接的阶段上。

### 快速入口

1. **设置 → Hooks → 添加一个 Hook。** 为其指定 **Hook ID**，选择 **类型**，并填写命令/脚本。
2. 在**连接管理器 → Hooks 标签页**中打开一个连接。
3. 在四个阶段下拉框之一中选择你的 Hook（连接前、连接后、断开前、断开后）。
4. 建立连接。Hook 输出会流入后台任务面板。

### Hook 类型

| 类型 | 执行内容 | 你需要提供 |
|------|--------------|------------------|
| **命令** | 一个可执行文件 | 一条命令及以空格分隔的参数。 |
| **脚本** | Bash 或 Python 文件 | 语言、文件路径，以及可选的解释器覆盖（留空为 `bash` / `python3`，按平台调整）。 |
| **Lua** | 进程内 Lua 脚本 | 文件路径与一组能力（见下文）。Lua 在 DBFlux 内部运行——无需外部解释器。 |

脚本在 DBFlux 的编辑器中编辑，默认存放在 `hooks/` 文件夹下。

#### Lua 能力

Lua Hook 只会获得你启用的能力：

| 能力 | 授予的权限 |
|------------|--------|
| **日志** | 默认开启；写入该 Hook 的输出。 |
| **环境读取** | 默认开启；读取环境变量。 |
| **连接元数据** | 默认开启；读取所连接配置文件的元数据。 |
| **受控的进程运行** | 默认关闭；调用 `dbflux.process.run(...)` 启动外部进程。 |

> 启用**受控的进程运行**会允许该 Hook 执行任意外部命令。当它处于开启状态时，DBFlux 会在 Hook 定义处以及各连接的绑定处显示安全警告。请仅对你信任的 Hooks 启用它。

内嵌的 Lua 运行时（可用 API、沙箱机制）记录在[Lua 脚本](LUA.md)。

### Hook 选项

| 选项 | 说明 |
|--------|-------|
| **已启用** | 处于关闭状态的 Hooks 会被跳过。 |
| **工作目录** | 进程/脚本的工作目录（Lua 不使用）。 |
| **环境变量** | 额外的 `KEY=value` 键值对。 |
| **继承父级环境** | 默认开启；将 DBFlux 的环境变量传递给该 Hook。 |
| **环境变量黑名单** | 要从继承环境中剔除的变量名。 |
| **超时（ms）** | 留空表示不超时。超时后整个进程组会被终止。 |
| **执行模式** | **Blocking**（默认）等待该 Hook 执行完毕；**Detached** 在后台运行，不阻塞连接/断开。 |
| **就绪信号**（Detached） | DBFlux 在继续之前、于该 Hook 输出中等待出现的文本。 |
| **失败时** | 失败策略——见下文。 |

DBFlux 始终会向进程类 Hooks 注入上下文环境变量：`DBFLUX_PROFILE_ID`、`DBFLUX_PROFILE_NAME`、`DBFLUX_DB_KIND`，以及在已知情况下的 `DBFLUX_HOST`、`DBFLUX_PORT`、`DBFLUX_DATABASE`。

> **密钥绝不会意外泄漏到 Hooks 中。** 除你配置的环境变量黑名单之外，DBFlux 始终会剔除名称中包含 `SECRET`、`TOKEN`、`PASSWORD` 或 `_KEY` 的继承变量，以及所有 `AWS_*` 变量。

### 失败策略

Hook 失败（非零退出、超时或出错）时的处理方式：

| 策略 | 效果 |
|--------|--------|
| **断开**（默认） | 中止该阶段——连接或断开流程就此停止。 |
| **警告** | 继续执行，但显示警告。 |
| **忽略** | 继续执行；失败仅记入日志。 |

### 阶段

| 阶段 | 执行时机 |
|-------|------|
| **连接前** | 连接建立之前。 |
| **连接后** | 连接成功之后。 |
| **断开前** | 断开连接之前。 |
| **断开后** | 断开连接之后。 |

一个连接的 Hooks 标签页为每个阶段提供一个下拉框（另有一个 “Extra” 输入框用于绑定额外的 Hook ID）。下拉框列出你在「设置 → Hooks」中定义的可复用 Hooks。每个 Hook 作为独立的后台任务运行，其 stdout/stderr 实时显示在后台任务面板中；每个 Hook 的输出上限为 4 MiB。
