# 连接到数据库 —— 高级设置

本文档涵盖连接管理器（Connection Manager）中除「主机、端口、用户、密码」这一基础配置之外的所有功能，包括：通过 SSH 隧道、代理或 AWS SSM 连接数据库；借助由提供程序驱动的认证配置文件（Auth Profile，如 AWS SSO）完成认证；以及从密钥管理器（Secret Manager）或参数存储（Parameter Store）中获取各项配置值，而无需手动输入。

日常操作流程（创建连接、浏览 Schema、执行查询）请参阅[使用指南](USAGE.md)。本文档从连接管理器的**访问**标签页和取值来源选择器开始讲起。

---

## 访问标签页：DBFlux 如何连接数据库

每个连接**只能**使用一种访问方式，通过**访问方式**（Access Method）下拉框指定。切换访问方式会清空其他方式的配置——一个连接要么是直连，要么是 SSH，要么是代理，要么是 SSM，不会是它们的组合。

| 访问方式 | 作用 |
| --- | --- |
| **直连** | 直接连接基础选项中配置的主机和端口。仍可按字段解析取值来源（参见[取值来源](#取值来源密钥管理器参数存储与认证会话)）。 |
| **SSH 隧道** | 先通过 SSH 主机建立本地端口转发，再经由该隧道连接。 |
| **代理** | 通过 SOCKS5 或 HTTP/HTTPS 代理转发连接。 |
| **SSM 端口转发** | 使用 AWS Systems Manager 将端口转发到目标实例，再经由该隧道连接。需要 `aws` 构建 feature。 |

### 点击连接后会发生什么

在驱动程序打开任何 Socket 之前，DBFlux 会先执行一条固定的连接前流水线：

1. **认证** —— 校验或刷新所选认证配置文件的会话（AWS SSO 的浏览器登录就发生在这一步）。
2. **解析取值** —— 解析每个字段的取值来源（密钥管理器、参数存储、环境变量、认证会话字段），并将解析结果填入配置。
3. **建立访问通道** —— 建立 SSH 隧道、代理连接或 SSM 会话（直连时此步不执行任何操作）。
4. **连接驱动并获取 Schema** —— 驱动程序建立连接，DBFlux 加载浅层 Schema。

连接 **Hook**（如果你绑定了任何 Hook）会围绕这条流水线，在**连接前**（PreConnect）、**连接后**（PostConnect）、**断开前**（PreDisconnect）和**断开后**（PostDisconnect）阶段执行。参见[设置与 Hooks](SETTINGS.md#connection-hooks)。

## SSH 隧道

SSH 隧道有两种用法：

- **引用已保存的隧道** —— 选择你在**设置 > SSH 隧道**中集中管理的隧道配置。当你需要在多个连接中复用同一个堡垒主机时，推荐这种方式。
- **内联配置** —— 直接在访问标签页上填写 SSH 字段。之后可以点击**保存为隧道**，将其提升为可复用的配置。

### SSH 字段

| 字段 | 说明 |
| --- | --- |
| **主机** / **端口** | SSH 服务器地址。端口通常为 `22`。 |
| **用户名** | SSH 登录用户。 |
| **认证方式** | **私钥**或**密码**。 |
| **私钥路径**（私钥方式） | 私钥文件的路径。**留空则使用 SSH agent 或默认密钥**（`~/.ssh/id_rsa` 等）。 |
| **密钥口令**（私钥方式） | 可选；勾选**保存**后存入操作系统密钥环。 |
| **密码**（密码方式） | 勾选**保存**后存入操作系统密钥环。 |

没有单独的「SSH agent」选项——选择**私钥**并将私钥路径留空，就是基于 agent 的认证方式。

**测试 SSH 连接**可在不保存连接的情况下验证隧道是否可用。

### SSH 密钥保存在哪里

口令和密码只保存在**操作系统密钥环**中，绝不会写入数据库。只有在密钥环可用时才会显示**保存**复选框；如果密钥环不可用，密钥不会被保存，你需要在每次会话中重新输入。参见[数据与隐私 → 密钥](DATA_AND_PRIVACY.md#secrets-and-the-os-keyring)。

## 代理

代理在**设置 > 代理**中统一管理；访问标签页只是**选择**一个已保存的代理并展示其详情。如果你还没有配置任何代理，标签页会给出跳转到设置的链接。

| 字段 | 说明 |
| --- | --- |
| **类型** | `SOCKS5`、`HTTP` 或 `HTTPS`。默认端口：SOCKS5 为 `1080`，HTTP/HTTPS 为 `8080`。 |
| **地址** / **端口** | 代理服务器的地址。 |
| **认证** | `None`，或带用户名的 `Basic`（密码保存在密钥环中）。 |
| **不使用代理** | 以逗号分隔、需要绕过代理的主机或匹配模式。支持 `*`（全部）、精确主机名，以及后缀匹配（前导点可省略），不区分大小写。**不支持 CIDR 网段。** |
| **已启用** | 代理配置被禁用时，连接会回退为**直连**（并给出警告），而不是直接失败。 |

> **注意：** 代理被禁用，或远程主机命中**不使用代理**规则，都会导致 DBFlux 静默地直接连接。如果你本以为流量会经过代理却没有，请优先检查这两项。

## 认证配置文件（AWS SSO 与共享凭据）

认证配置文件保存由提供程序驱动的认证信息，由 DBFlux 在连接时解析。它们在**设置 > 认证配置文件**中创建，并按连接分别选择。当前构建中内置的提供程序**仅限 AWS**：

| 提供程序 | 适用场景 |
| --- | --- |
| **AWS SSO** | 通过 IAM Identity Center（SSO）登录，解析出账户和角色。 |
| **AWS SSO Session** | 可复用的 SSO 会话（起始 URL + 区域 + 作用域），供 AWS SSO 配置文件继承。 |
| **AWS Shared Credentials** | 写入 `~/.aws/credentials` 的具名配置文件（访问密钥 / 密钥 / 可选会话令牌）。 |

外部注册的 RPC 认证提供程序还可以在此添加更多条目，参见 [RPC 服务](RPC_SERVICES_CONFIG.md)。

> DBFlux 会从你的 `~/.aws/config` 实时同步 AWS 配置文件，这些条目显示为**只读**：你可以在这里选择，但不能编辑；如需修改，请直接编辑 AWS 配置文件。

### 创建 AWS SSO 配置文件

表单由提供程序驱动。创建 AWS SSO 配置文件需要填写：

| 字段 | 说明 |
| --- | --- |
| **配置文件名称** | 例如 `dev`。 |
| **SSO 会话** | 可选，引用一个 **AWS SSO Session** 配置文件。设置后，起始 URL 和区域将从该会话继承，对应的内联字段会置灰。 |
| **SSO 起始 URL** | 你的 Identity Center 门户 URL（使用会话时可跳过）。 |
| **区域** | 例如 `us-east-1`。 |
| **账户** | **登录后才**会填充的下拉框，列出当前 SSO 会话可访问的账户。 |
| **角色** | 选定账户后才会填充的下拉框。 |

**账户**和**角色**下拉框是动态的：它们依赖一个有效的 SSO 会话，并会随依赖项变化而刷新。如果下拉框为空，请先登录（见下文）。

**SSO 向导**（AWS SSO Wizard）以分步引导的方式提供相同的流程：填写名称、起始 URL 和区域后，它会帮你登录，并列出可选的账户和角色。

### SSO 登录流程

当连接（或账户/角色下拉框）需要 SSO 会话时，DBFlux 会弹出登录对话框：

- **自动打开浏览器**访问验证 URL。
- 如果浏览器无法打开，对话框会显示该 URL 并提供**复制 URL** 操作，方便你手动打开。
- 在浏览器中完成认证后，DBFlux 会自动继续后续流程。
- **SSO 登录 5 分钟后超时。**

### 按连接选择认证配置文件

- **直连模式** —— 认证配置文件*可选*。仅在需要解析 AWS 云密钥管理 / AWS 参数存储 / 认证会话字段取值来源时才用到（见下一节）。
- **SSM 模式** —— 认证配置文件**必填**。
- 如果任何字段使用了由认证提供程序支持的 AWS 云密钥管理 / AWS 参数存储取值来源，则**必须**指定匹配的认证配置文件，否则连接会在建立之前被拒绝。

每个配置文件行都有**管理**、**登录**和**刷新**按钮。**登录**按钮仅在所选配置文件确实需要登录时可用。

## SSM 端口转发（托管访问）

「托管」访问是指由提供程序为你打通到目标主机的通路。当前随附的实现是 **AWS SSM 端口转发**（需要 `aws` feature）。

| 字段 | 说明 |
| --- | --- |
| **实例 ID** | 目标 EC2 实例。支持取值来源选择器。 |
| **区域** | 留空时默认为 `us-east-1`。 |
| **远程端口** | 实例上需要转发到的端口。 |
| **认证配置文件** | **必填** —— 用于启动 SSM 会话的 AWS 配置文件。 |

**本地**隧道端口由 DBFlux 和操作系统自动分配，只有远程端口可以配置。

## 取值来源：密钥管理器、参数存储与认证会话

任何单个连接字段（主机、密码等）都可以从外部来源取值，而不必直接填写固定值。点击字段旁边的取值来源选择器，然后选择：

| 来源 | 作用 |
| --- | --- |
| **字符**（Literal） | 直接输入的值（默认）。 |
| **环境变量**（Environment Variable） | 按名称从环境变量读取。 |
| **AWS 云密钥管理**（Secret Manager） | 从密钥提供程序（AWS Secrets Manager）获取。 |
| **AWS 参数存储**（Parameter Store） | 从参数提供程序（AWS SSM Parameter Store）获取。 |
| **认证会话字段**（Auth Session Field） | 从已解析的认证配置文件会话或凭据中提取指定字段。 |

补充说明：

- AWS 云密钥管理 / AWS 参数存储来源可以指向 JSON 密钥中的某个 **JSON 键**，因此一份 JSON 文档就能为多个字段供值。
- 解析结果会缓存 **5 分钟**，避免每次重连都重新获取。
- 由认证提供程序支持的 AWS 云密钥管理 / AWS 参数存储来源**要求连接上配置了认证配置文件**（连接前强制校验）。

## 表单模式与直接填写 URI

大多数关系型驱动程序都支持两种填写方式：逐项填写各个字段，或直接填写一个连接字符串。基础选项上的 **Use URI** 开关用于在两者之间切换。

- URI 模式适用于 **PostgreSQL、MySQL/MariaDB、SQL Server、MongoDB 和 Redis**；SQLite、DynamoDB、CloudWatch 和 InfluxDB 则使用各自基于字段的表单。
- **开启** URI 模式时，以单个 URI 字段为准，其他字段会被忽略；**关闭**时则使用各个字段。
- URI 中内嵌的密码会被提取出来单独保存（保存时存入密钥环），不会留在 URI 文本里。
- 通过 SSH/代理/SSM 隧道连接时，即使你填写的是 URI，DBFlux 也始终使用基于字段的配置（重写为 `127.0.0.1:<本地端口>`）。

## 快速参考：常见易错点

- **每个连接只能使用一种访问方式。** 切换方式会清空其他方式的配置。
- **密钥保存在操作系统密钥环中**，不会写入 DBFlux 数据库。密钥环不可用时，「保存」复选框会消失，密钥也不会被保留。
- **代理被禁用或命中不使用代理规则时，会静默直连。**
- **`No Proxy`（不使用代理）不支持 CIDR** —— 请填写主机或后缀，而不是 IP 网段。
- **SSM 和由认证提供程序支持的取值来源都需要认证配置文件。**
- **内置的认证提供程序仅限 AWS**（SSO、SSO Session、Shared Credentials），其他提供程序来自外部 RPC 服务。
- **SSO 登录会自动打开浏览器，并在 5 分钟后超时。**
