# 시각적 쿼리 빌더

SQL 연결에서는 SQL을 직접 작성하지 않고 쿼리를 조합할 수 있습니다. 테이블의 데이터 그리드 도구 모음에서 **빌더**를 클릭하면 오른쪽 레일 패널이 열립니다. 문서 컬렉션에는 별도의 빌더가 있으며 [문서 컬렉션](#문서-컬렉션)에서 설명합니다.

패널 상단에는 모드 선택기(**SELECT**, **UPDATE**, **DELETE**)가 있고, 변경할 때마다 다시 생성되는 실시간 SQL 미리보기가 있습니다. 미리보기는 항상 표시됩니다. **실행**을 누르면 실행하고, (SELECT 모드에서는) **편집기에서 열기**를 누르면 생성된 SQL을 일반 쿼리 편집기에 넣습니다. 헤더에는 **저장**과 **재설정**이 있습니다.

| 키 | 동작 |
|------|--------|
| `Cmd+Enter` / `Ctrl+Enter` | 실행 |
| `Cmd+E` / `Ctrl+E` | 편집기에서 열기 (SELECT 모드) |
| `Cmd+S` / `Ctrl+S` | 저장 |
| `Cmd+Shift+S` / `Ctrl+Shift+S` | 다른 이름으로 저장 |
| `Cmd+Backspace` / `Ctrl+Backspace` | 재설정 |

## SELECT 작성하기

SELECT 본문에는 위에서 아래로 채우는 섹션이 있습니다:

- **열** — 프로젝션(어떤 열을 선택할지).
- **필터** — `WHERE` 조건 트리. 조건자는 AND/OR 그룹으로 중첩할 수 있어 복잡한 조건을 시각적으로 만들 수 있습니다.
- **조인** — 별칭과 `ON` 조건이 있는 추가 테이블.
- **그룹화 / 집계** — 아래를 참조하세요.
- **정렬** — `ORDER BY` 항목.
- **제한과 오프셋** — 페이징 범위.

SQL 미리보기는 매개변수화되어 있습니다. 리터럴 값은 활성 방언(SQLite, PostgreSQL, MySQL/MariaDB 또는 SQL Server)에 맞는 자리 표시자로 출력됩니다.

## GROUP BY와 집계

**그룹화 / 집계** 섹션에서 그룹 열과 집계를 추가합니다. 지원되는 집계 함수는 `COUNT`, `COUNT(*)`, `COUNT(DISTINCT)`, `SUM`, `AVG`, `MIN`, `MAX`입니다. 각 집계에는 함수와 열에서 자동 생성되는 편집 가능한 별칭이 붙습니다.

쿼리가 그룹화되면:

- **열** 섹션은 유효한 `SELECT`의 읽기 전용 미리보기(그룹 열 뒤에 집계 별칭)로 대체됩니다.
- **HAVING** 섹션이 나타납니다. 필터와 같은 조건자 편집기를 사용하지만 `HAVING`에 적용됩니다.
- **정렬** 항목은 그룹 열과 집계 별칭으로 제한되며, 잘못된 항목은 눈에 보이는 오류와 함께 거부됩니다.

그룹화된 결과가 데이터 그리드에서 어떻게 동작하는지는 [Aggregated results](RESULTS.md#집계된-결과)에서 설명합니다.

## 스키마 인식 자동 완성

빌더의 한 줄 입력(필터, 정렬, 프로젝션 열, 조인 대상 테이블, 조인 `ON`의 양쪽)은 라이브 스키마와 빌더 자체 스펙에서 가져온 인라인 제안을 제공합니다. 대상은 소스 테이블 열, 선언된 조인 별칭, 조인된 테이블 열(백그라운드에서 지연 조회)입니다. `<alias>.`를 입력하면 제안이 해당 별칭의 열로 한정됩니다. 일치는 접두사 기준입니다.

| 키 | 동작 |
|------|--------|
| `Up` / `Down` | 제안 사이를 이동 |
| `Tab` / `Enter` | 강조된 제안 확정 |
| `Esc` (또는 포커스 이탈) | 닫기 |

데이터 그리드의 `WHERE` 필터 입력에서도 같은 자동 완성을 사용할 수 있습니다([Filtering results](RESULTS.md#결과-필터링) 참조).

## 저장된 쿼리

빌더는 연결 프로필별로 저장했다가 나중에 다시 열 수 있습니다. 저장된 쿼리는 프로필에 속하며 이름은 고유해야 합니다. 저장된 쿼리는 다른 연결로 가져올 수도 있습니다. 가져올 때 DBFlux는 불러오기 전에 참조된 테이블이 대상 연결에 존재하는지 확인합니다.

## 시각적 UPDATE와 DELETE

모드 선택기를 **UPDATE**나 **DELETE**로 바꾸면 변경 작업을 만들 수 있습니다. 두 모드 모두 `WHERE` 절에 같은 필터 편집기를 재사용하며, UPDATE는 `SET` 열을 위한 할당 섹션을 추가합니다(원시 표현식 할당 포함). SQL 미리보기는 전체 과정에서 계속 표시됩니다.

변경 작업은 연결의 읽기 전용 상태와 행위자 컨텍스트를 조합한 정책의 대상입니다:

| 정책 | 효과 |
|--------|--------|
| 허용 | 변경을 실행할 수 있습니다. |
| 읽기 전용 | 실행이 차단됩니다(예: 읽기 전용 프로필). |
| 승인 필요 | 실행 전에 승인이 필요합니다. |

**실행 모드.** **실행** 섹션은 세 가지 모드를 제공하며, 행 수 추정치, 드라이버의 트랜잭션 지원, 기본 키 사용 가능 여부를 바탕으로 기본값이 자동 제안됩니다. 제안을 바꾸면 장단점을 비교하는 모달이 표시됩니다.

| 모드 | 동작 |
|------|----------|
| **단일 트랜잭션** | 전체 변경을 하나의 트랜잭션으로 처리합니다. |
| **청크 단위 트랜잭션** | 테이블의 기본 키를 따라 키셋 페이지 나누기 방식으로 청크를 나눕니다(청크 크기는 1000–10000으로 제한되며 기본값은 5000). 각 청크는 자체 트랜잭션이고 작업 패널에 항목을 표시하며, 청크 사이에서 취소할 수 있고 실패하면 롤백합니다. |
| **직접 실행** | 트랜잭션 래퍼가 없습니다(자동 커밋). 드라이버가 트랜잭션을 지원하지 않을 때 사용합니다. |

**위험 쿼리 게이트.** `WHERE`가 없는 `UPDATE`나 `DELETE`는 실행 전에 위험 쿼리 확인([위험 쿼리 확인](EDITOR.md#위험-쿼리-확인) 참조)을 거칩니다.

## 문서 컬렉션

이 기능을 제공하는 드라이버(MongoDB)의 컬렉션에는 find 쿼리와 간단한 집계를 위한 시각적 빌더가 있습니다. 컬렉션 헤더에서 **빌더**를 클릭하면 오른쪽 레일에 열리며, 다시 클릭하거나 레일의 닫기 버튼을 누르면 숨겨집니다. 탭이 열려 있는 동안 초안은 유지됩니다. DynamoDB처럼 빌더가 없는 문서 드라이버에서는 버튼이 비활성화되고 툴팁에 그 이유가 표시되며, 쿼리 칸은 계속 사용할 수 있습니다.

레일에는 **Find** / **Aggregate** 모드 전환, 아래에서 설명하는 카드, 그리고 바닥글 위에 고정된 드라이버 고유 구문의 쿼리 미리보기가 있습니다. 바닥글에서는 쿼리를 실행하거나(Find 모드에서는 **찾기**, Aggregate 모드에서는 **파이프라인 실행**) 미리보기를 쿼리 편집기에서 엽니다(**편집기에서 열기**).

### Find 모드

| 카드 | 만드는 내용 |
|------|-------------|
| **필터** | *모두 충족*(`$and`) 또는 *하나 이상 충족*(`$or`)으로 결합한 조건이며, 그룹을 중첩할 수 있습니다. |
| **프로젝션** | 포함하거나 제외할 필드입니다. `_id`는 항상 반환되므로 결과 행은 계속 편집할 수 있습니다. |
| **정렬, 제한, 건너뛰기** | 각각 오름차순 또는 내림차순인 정렬 키, 그리고 제한과 건너뛰기 값입니다. |

조건은 필드, 연산자, 값으로 이루어집니다. 제공되는 연산자는 스키마 표본에서 해당 필드의 유형에 따라 `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$regex`, `$exists`, `$elemMatch`, `$size`, `$all` 중에서 정해집니다. 표본에서 둘 이상의 유형을 가진 필드는 표시되며, 그 조건에는 각 유형의 연산자가 제공됩니다. 값 입력 방식은 연산자에 따라 다릅니다.

| 연산자 또는 유형 | 값 입력 방식 |
|------------------|--------------|
| `$in`, `$nin`, `$all` | 값 목록이며 값마다 칩 하나입니다(값을 입력하고 `Enter`를 누릅니다). |
| `$exists`, 그리고 불리언 필드의 `$eq` / `$ne` | true / false 스위치입니다. |
| `$regex` | 패턴이며 `/pattern/flags` 또는 구분자 없는 패턴입니다. |
| `$size` | 요소 개수(정수)입니다. |
| `$elemMatch` | 배열 요소 하나가 충족해야 하는 조건입니다. |
| 날짜 필드 | `YYYY-MM-DD`, `YYYY-MM-DD HH:MM`(UTC) 또는 RFC 3339 타임스탬프입니다. |
| ObjectId 필드 | 16진수 24자리입니다. |

필드는 스키마 뷰의 표본을 바탕으로 한 선택기에서 고릅니다. 선택기는 중첩 경로, 경로마다의 유형 태그, 필드가 나타나는 비율을 보여 줍니다. 표본에 없는 경로는 직접 입력하고 `Enter`로 사용할 수 있으며, 샘플에 없음으로 표시됩니다.

**찾기**는 칸과 같은 방식으로 쿼리 바를 통해 쿼리를 실행합니다. 결과는 일반 문서이며 편집할 수 있고, 개수가 세어지며, 쿼리 기록에 남습니다.

### 쿼리 바와의 동기화

레일이 열려 있는 동안 빌더와 `filter`, `project`, `sort`, `limit` 칸은 양방향으로 동기화됩니다. 빌더에서 편집하면 바뀐 칸이 다시 쓰이고, 칸을 편집하면 빌더가 갱신됩니다. 건너뛰기에는 칸이 없으며 레일이 열려 있는 동안 적용됩니다.

칸에 `$expr`처럼 빌더가 표시할 수 없는 절이 있으면, 빌더는 이해할 수 있는 부분을 보여 주고 나머지는 읽기 전용으로 두며 두 가지 선택지가 있는 카드를 표시합니다. 그 칸을 바꾸게 될 빌더 편집은 선택할 때까지 대기하고, 그동안 **찾기**는 비활성화됩니다.

| 선택지 | 효과 |
|--------|------|
| **텍스트 유지** | 대기 중인 빌더 편집을 버리고 칸에 작성된 내용을 유지합니다. |
| **빌더로 다시 쓰기** | 칸을 빌더의 쿼리로 바꾸고, 빌더가 표시할 수 없던 절은 버립니다. |

### Aggregate 모드

**그룹** 카드에서 그룹 단계를 추가하면 **Aggregate**로 전환되고, 제거하면 **Find**로 돌아갑니다. Aggregate 모드에는 집계 파이프라인을 실행할 수 있는 드라이버가 필요합니다.

- **그룹 기준**에는 필드를 0개 이상 지정할 수 있으며, 지정하지 않으면 모든 문서가 하나의 그룹이 됩니다.
- **누산기**는 `$count`, `$sum`, `$avg`이며 각각 출력 이름을 가집니다. `$sum`과 `$avg`에는 숫자 필드가 필요합니다.
- 필터는 `$match` 단계가 되며 **편집** 버튼이 있는 요약으로 표시됩니다.
- **프로젝션**은 사용되지 않습니다. 출력 필드는 그룹 키와 누산기입니다.
- 정렬 키는 그룹 키나 누산기만 될 수 있습니다.

**파이프라인 실행**은 파이프라인을 컬렉션의 집계 뷰에 쓰고 그곳에서 실행합니다. 그룹화된 행은 계산된 값이므로 편집할 `_id`가 없습니다. 결과는 읽기 전용이며 이를 알리는 배너가 표시됩니다. 빌더가 Aggregate 모드인 동안에는 쿼리 바와 집계 뷰에 칸과 파이프라인 편집기 대신 파이프라인 요약이 표시됩니다.

### 저장된 문서 쿼리

레일 헤더에서 쿼리 이름을 입력하고 **쿼리 저장**을 클릭합니다. 저장된 쿼리는 컬렉션, 즉 연결 프로필, 데이터베이스, 컬렉션 이름에 속합니다. 이미 있는 이름으로 저장하면 그 쿼리를 대체합니다. **저장된 쿼리**에서 목록을 볼 수 있으며, 하나를 열면 저장할 때의 모드로 불러옵니다.

### 제한 사항

- 16진수 24자리로 된 텍스트 값은 드라이버가 그런 문자열을 변환하기 때문에 ObjectId로 실행됩니다. 빌더는 이 값을 ObjectId로 입력하도록 요구하므로, 그런 문자열을 담은 텍스트 필드는 텍스트로 검색할 수 없습니다.
- 소수 값은 double로 비교되므로 `Decimal128` 필드와 일치하지 않습니다.
- 칸에서 `{"$date": "..."}`는 `2024-03-09T14:30:05Z` 같은 RFC 3339 타임스탬프만 받습니다.
- 빌더에는 쓰기 단계(`$out`, `$merge`)가 없으며 업데이트나 삭제를 만들지 않습니다.
- 저장된 쿼리를 삭제할 때 확인을 묻지 않습니다.
