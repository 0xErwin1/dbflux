# 보안 정책
## 취약점 보고

취약점이 의심된다면 GitHub Security Advisories를 통해 비공개로 보고해 주시기 바랍니다:

**https://github.com/0xErwin1/dbflux/security/advisories/new**

의심되는 취약점에 대해 공개 이슈를 열지 말아 주시기 바랍니다. DBFlux 버전, 플랫폼, 관련된 드라이버(있다면), 그리고 이를 재현하는 최소한의 단계가 함께하면 보고가 훨씬 더 유용해집니다.

기계가 읽을 수 있는 연락처 정보는 [`/.well-known/security.txt`](https://dbflux.dev/.well-known/security.txt)에 게시되어 있습니다.

## 지원되는 버전

수정 사항은 현재 릴리스 브랜치에 반영됩니다. DBFlux는 `main`에서 개발하며 마이너마다 `release/vX.Y` 브랜치를 만들고, 해당 브랜치는 수명이 다할 때까지 선별된 수정 사항을 받습니다. 그보다 오래된 마이너는 수정 사항을 받지 않습니다. 브랜치와 채널이 어떻게 동작하는지는 [릴리스 절차](docs/RELEASE.md)에 설명되어 있습니다.

이전 마이너를 실행 중이라면, 보안 보고에 대한 답변은 현재 마이너로 업그레이드하는 것입니다.

## 설계상 알려진 제한 사항

다음은 취약점이 아니라 문서화된 동작입니다. 이에 대한 보고는 설계 논의로 환영하지만, 미공개 위험으로 취급되지는 않습니다.

- **MCP 인증은 프로세스 신원만으로 이루어집니다.** `--client-id`를 제시하는 것이 유일한 인증 신호이므로, 클라이언트 ID를 아는 모든 로컬 프로세스가 연결할 수 있습니다. 이는 암호학적 보장이 아니며, 추가 인증 계층 없이 MCP 서버를 localhost 밖으로 노출해서는 안 됩니다. [AI + MCP 통합](docs/MCP_AI_INTEGRATION.md)을 참조하세요.
- **연결 훅과 Lua 스크립트는 사용자가 구성한 코드를 실행합니다.** 이는 설계상 DBFlux 프로세스의 권한으로 실행되며, 그것이 훅의 본질입니다. [설정과 훅](docs/SETTINGS.md)과 [Lua 스크립팅](docs/LUA.md)을 참조하세요.
- **감사 로그는 로컬에 기록됩니다.** 감사 로그는 해당 머신에서 발생한 일을 기록하며, 데이터 디렉터리를 읽을 수 있는 모든 것이 이를 읽을 수 있습니다. [데이터와 개인정보](docs/DATA_AND_PRIVACY.md)를 참조하세요.

## 비밀의 보관 위치

자격 증명은 운영 체제 키링에 보관되며 연결 프로필 파일에는 절대 저장되지 않고, 감사 로그는 쿼리 텍스트 자체가 아니라 쿼리 텍스트의 지문을 저장합니다. [데이터와 개인정보](docs/DATA_AND_PRIVACY.md)는 무엇이 어디에 기록되는지, 그리고 이를 검사하거나 제거하는 방법을 설명합니다.
