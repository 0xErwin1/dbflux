# 스키마 탐색

사이드바에는 두 개의 탭이 있습니다:

- **연결** — 스키마 트리(데이터베이스, 스키마, 테이블/컬렉션, 열, 인덱스,
  그리고 드라이버가 지원하는 경우 루틴 폴더).
- **스크립트** — 저장된 쿼리 파일, 스크립트 훅, 기타 사용자 파일을 위한 파일 및
  폴더 관리.

두 탭 사이는 `q` 또는 `e`로 전환합니다.

## 트리 탐색

- `j`/`k`(또는 `Down`/`Up`) — 선택 항목을 이동합니다.
- `h`는 현재 노드를 접고, `l`은 펼칩니다. `Space`는 펼치기/접기를 전환합니다.
- `g`는 첫 항목으로, `Shift+g`는 마지막 항목으로 이동합니다. `Home`/`End`도
  같은 역할을 합니다.
- `Ctrl+d`/`Ctrl+u`(또는 `PageDown`/`PageUp`) — 긴 목록을 페이지 단위로
  넘겨 봅니다.
- `/`는 사이드바 검색/필터에 포커스를 맞춥니다.
- `Enter`는 선택한 항목을 엽니다(예: 테이블을 열면 데이터 그리드가 열립니다).
- `r`은 스키마를 새로고침하고, `d`는 활성 연결을 끊습니다.
- `m`은 선택한 항목의 상황에 맞는 메뉴를 엽니다.

## 외부 스크립트 폴더

Scripts 보기에서는 여러 프로젝트가 공유하는 SQL 파일 저장소처럼 DBFlux 자체 스크립트 폴더 밖에 있는 스크립트를 복사하지 않고 나열할 수 있습니다. Scripts 보기의 `+` 메뉴에서 **외부 폴더 추가**를 선택하거나 명령 팔레트에서 **외부 스크립트 폴더 추가…**를 실행한 뒤 폴더를 고릅니다.

- 폴더는 사용자의 스크립트 아래에 이름을 레이블로 표시됩니다. 편집기가 여는 파일(`.sql`, `.js`, `.redis`, `.lua`, `.py`, `.sh` 및 기타 스크립트 형식)만 나열됩니다. 다른 파일만 들어 있는 하위 폴더는 숨겨지고, 빈 폴더는 표시되므로 방금 만든 폴더도 보입니다. 폴더 밖으로 나가는 심볼릭 링크는 나열되지 않으며, 그 링크를 통해 아무것도 쓰지 않습니다.
- 스크립트는 제자리에서 열리고 저장되므로 파일이 폴더와 동기화된 상태로 유지됩니다. 그 안에서 파일과 하위 폴더를 만들고 이름을 바꾸고 삭제하는 방법은 자체 스크립트 폴더와 같습니다. 서로 다른 두 폴더 사이에서 파일을 옮기는 것은 거부됩니다.
- DBFlux는 폴더를 감시하지 않습니다. DBFlux 밖에서 추가되거나 바뀐 파일을 반영하려면 폴더에서 `r`을 누르거나 메뉴에서 **새로 고침**을 선택하세요. DBFlux를 시작할 때마다 폴더를 백그라운드에서 검색하기도 합니다.
- 폴더가 이동, 삭제, 마운트 해제되었거나 읽을 수 없으면 다시 사용할 수 있게 되거나 제거할 때까지 **사용할 수 없음**으로 표시된 채 목록에 남습니다. 폴더 메뉴에서 읽을 수 없는 이유를 확인할 수 있습니다.
- **사이드바에서 제거**(`x`)는 폴더를 잊기만 합니다. 파일은 절대 건드리지 않으며, DBFlux에서 폴더 자체의 이름을 바꾸거나 옮기거나 삭제할 수 없습니다.
- 외부 폴더는 AI 클라이언트와 공유되지 않습니다. MCP 스크립트 도구는 DBFlux 자체 스크립트 폴더만 봅니다.

## 지연 로딩

스키마는 지연 로딩됩니다. 연결 시 DBFlux는 얕은 메타데이터(이름)를 가져옵니다.
상세 메타데이터 — 열, 인덱스 등 — 는 노드를 펼칠 때 필요한 시점에 가져옵니다.
덕분에 큰 데이터베이스에서도 초기 연결이 빠르게 유지됩니다.

## 루틴 / 저장 프로시저

루틴 지원을 알리는 드라이버(첫 구현은 PostgreSQL)의 경우 스키마 트리에 함수,
프로시저, 집계, 윈도우 루틴을 담은 **루틴** 폴더가 포함됩니다. 루틴을 열면 그
정의를 보여 주는 읽기 전용 코드 문서가 열립니다. 이 문서는 편집할 수 없지만
텍스트를 선택하고 복사할 수는 있으며, 실행과 변경 관련 컨트롤은 숨겨집니다.

## 스키마 다이어그램

드라이버가 외래 키 지원을 알리는 관계형 연결(예: PostgreSQL, MySQL/MariaDB,
SQLite, SQL Server)은 테이블과 외래 키를 다이어그램으로 그릴 수 있습니다.
사이드바의 상황에 맞는 메뉴에서 엽니다:

- 불러온 데이터베이스에서 **스키마 다이어그램 보기**를 선택하면 그 데이터베이스의
  모든 테이블을 최대 100개까지 그립니다. 테이블이 더 많으면 "처음 100개 테이블만
  표시합니다 — 스키마에 테이블이 더 있습니다." 알림이 표시됩니다.
- 테이블에서 **관계 보기**를 선택하면 그 테이블, 그 테이블이 참조하는 테이블,
  그 테이블을 참조하는 테이블을 그립니다.

다이어그램은 별도 탭에서 열리며, 같은 다이어그램을 다시 열면 그 탭으로
전환됩니다. 로딩은 백그라운드 작업("스키마 다이어그램: _데이터베이스_")으로
실행되며 작업 패널에서 취소할 수 있습니다. 각 테이블은 `PK`, `FK`, `NN`(not
null) 배지와 함께 열을 나열하고, 선은 각 외래 키를 그 키가 참조하는 테이블에
연결합니다.

| 도구 모음 컨트롤 | 동작 |
|---|---|
| `+` / `-` | 25%에서 400% 사이로 확대 / 축소합니다. 현재 배율이 옆에 표시됩니다. |
| **재설정** | 100% 배율과 처음 위치로 돌아갑니다. |
| **정렬** | 직접 옮긴 테이블의 위치를 버리고 레이아웃을 다시 계산합니다. |
| **화면에 맞추기** | 모든 테이블이 보이도록 배율과 위치를 조정합니다. |
| 레이아웃 드롭다운 | **왼쪽-오른쪽**(기본값)은 외래 키를 가진 테이블을 왼쪽에, 그 테이블이 참조하는 테이블을 오른쪽에 배치합니다. **스노우플레이크**는 한 테이블을 가운데에 두고 직접 연결된 테이블을 그 주위에 원형으로 배치합니다. 가운데 테이블은 **관계 보기**에서는 선택한 테이블이고, 데이터베이스 다이어그램에서는 연결이 가장 많은 테이블입니다. **컴팩트**는 테이블을 이름순으로 촘촘한 격자에 배치합니다. 레이아웃을 바꾸면 배율, 위치, 옮긴 테이블도 초기화됩니다. |
| **내보내기** | **DBML로 복사** 또는 **SQL로 복사**는 다이어그램에 표시된 테이블을 클립보드로 복사합니다. SQL은 `CREATE TABLE` 문과 외래 키용 `ALTER TABLE ... ADD CONSTRAINT`로 구성됩니다. |
| 테이블 _N_개 · 관계 _M_개 | 다이어그램에 표시된 테이블과 외래 키의 수입니다. |
| **타입** / **인덱스** | 열 타입을 표시합니다(기본값 켜짐) / 각 테이블 아래에 인덱스 목록을 표시합니다(기본값 꺼짐). |

빈 공간을 드래그하면 뷰가 이동하고, 테이블을 드래그하면 그 테이블이
이동하며(격자에 맞춰짐), 마우스 휠은 포인터 위치를 중심으로 확대/축소합니다.
테이블을 클릭하면 선택됩니다. 마우스 오른쪽 버튼으로 클릭하면 **확대**,
**축소**, **레이아웃**, **다른 형식으로 복사**가 있는 상황에 맞는 메뉴가
열립니다. 테이블을 마우스 오른쪽 버튼으로 클릭하면 그 테이블도 선택되며,
테이블이 선택된 동안에는 메뉴에 **스키마 검사**가 추가됩니다. **스키마 검사**를
선택하거나 테이블을 더블 클릭하면 오른쪽 검사기 레일에 그 테이블이 열리며
**테이블**, **열**, **인덱스**, **외래 키** 섹션이 표시됩니다. 마지막 두 섹션은
테이블에 인덱스가 있거나 테이블이 외래 키를 선언한 경우에만 나타납니다. 키보드
단축키는 [키보드 참조](KEYBOARD.md#스키마-다이어그램)에 있습니다.
