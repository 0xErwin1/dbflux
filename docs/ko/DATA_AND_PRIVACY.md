# 데이터 및 개인정보

DBFlux가 데이터를 저장하는 위치, 자격 증명을 보호하는 방식, 감사 로그에 기록되는
내용, 그리고 백업하거나 완전히 초기화하는 방법을 설명합니다.
## 한눈에 보기

| 데이터 | 저장 위치 |
|-----------|----------------|
| 연결 프로필, 설정, 기록, 저장된 차트/쿼리, 감사 로그 | 데이터 디렉터리의 단일 SQLite 파일인 `dbflux.db` |
| 열려 있는 탭 / 세션 | 같은 `dbflux.db`에 더해 디스크의 스크립트 파일과 스크래치/섀도 파일 |
| 비밀번호, 패스프레이즈, API 비밀 | **OS 키링** — 절대 `dbflux.db`에 저장하지 않음 |
| IPC/MCP 인증 토큰 | 설정 디렉터리의 `0600` 파일 |

DBFlux는 거의 모든 것을 단일 SQLite 데이터베이스에 보관합니다. 비밀은 의도적으로
예외입니다. 비밀은 운영 체제의 키링에 저장되며, 데이터베이스에는 그 *참조*만
저장합니다.

---

## 데이터 위치

DBFlux는 플랫폼의 표준 디렉터리를 사용합니다.

| 플랫폼 | 데이터 디렉터리 | 설정 디렉터리 |
|----------|----------------|------------------|
| **Linux** | `~/.local/share/dbflux/` | `~/.config/dbflux/` |
| **macOS** | `~/Library/Application Support/dbflux/` | `~/Library/Application Support/dbflux/` |
| **Windows** | `%APPDATA%\dbflux\` | `%APPDATA%\dbflux\` |

데이터 디렉터리에는 다음이 들어 있습니다:

- **`dbflux.db`** — 통합 데이터베이스(자세한 내용은 아래 [데이터베이스에 저장되는
  것](#데이터베이스에-저장되는-것) 참조).
- **`sessions/`** — 열려 있는 편집기 탭의 스크래치/섀도 파일: 제목 없는 콘텐츠와
  저장하지 않은 편집 내역의 복구 사본.
- **`ipc_auth_token`** — IPC/MCP 인증 토큰([아래](#ipcmcp-인증-토큰) 참조).
- **`ssh_known_hosts`** — 수락한 SSH 호스트 키(TOFU).

DBFlux는 더 이상 설정 디렉터리를 사용하지 않습니다. 이전 버전은 IPC 인증 토큰과
SSH known-hosts를 이곳에 저장했으므로, 업그레이드 후에도 남아 있는 파일이 있으면
삭제해도 됩니다.

### 안정 vs. 나이틀리

나이틀리 빌드는 별도의 데이터베이스 파일인 `dbflux-nightly.db`를 사용하므로,
프리릴리스 마이그레이션이 안정 데이터를 건드릴 일이 없습니다. 안정 빌드와 릴리스
후보 빌드는 모두 `dbflux.db`를 사용합니다.

나이틀리 빌드가 안정 데이터베이스를 공유하도록 만들 수 있습니다. **설정 → 일반 →
스토리지 → 안정 데이터베이스 사용**(다음 실행 시 적용)을 켜면 됩니다. 내부적으로는
데이터 디렉터리에 빈 `use-stable-db` 마커 파일을 두는 것뿐입니다.

## 데이터베이스에 저장되는 것

`dbflux.db`는 단일 SQLite 파일입니다. 테이블은 접두사별로 묶여 있습니다:

| 접두사 | 내용 |
|--------|----------|
| `cfg_*` | 설정: 연결 프로필, 인증/프록시/SSH 터널 프로필, RPC 서비스, 연결 훅, MCP 거버넌스, 그리고 일반/감사 설정. (비밀 *값*은 여기에 **없습니다** — 키링 참조만 저장합니다.) |
| `st_*` | 워크벤치 상태: 열려 있는 세션/탭, **쿼리 기록**(전체 쿼리 텍스트), 저장된 쿼리, 최근 항목, 스키마 캐시, UI 상태. |
| `aud_*` | 감사 로그와 저장된 감사 필터. |
| `viz_*` | 저장된 차트와 대시보드. |
| `qry_*` | 시각적 쿼리 빌더의 저장된 쿼리. |
| `sys_*` | 내부용: 스키마 마이그레이션 버전, 앱 메타데이터. |

> **쿼리 기록에 대한 참고.** 워크벤치 쿼리 기록(`st_*`)은 실행한 쿼리의 **전체
> 텍스트**를 평문으로 저장합니다. 이는 기본적으로 쿼리 텍스트를 지문으로 대체하는
> 감사 로그(아래 참조)와는 별개입니다. 쿼리 텍스트를 보관하지 않으려면 설정 → 일반의
> **최대 기록 항목 수**를 낮추거나, 편집기의 기록 뷰에서 기록을 지우십시오.

## 비밀과 OS 키링

비밀번호, SSH 패스프레이즈, 프록시 자격 증명, 프로바이더 비밀은 운영 체제의 키링에
저장되며 `dbflux.db`에는 저장되지 **않습니다**.

| 플랫폼 | 키링 백엔드 |
|----------|-----------------|
| **Linux** | Secret Service (GNOME Keyring / KWallet, libsecret 경유) |
| **macOS** | Keychain |
| **Windows** | Windows Credential Manager |

모든 항목은 **`dbflux`**라는 서비스 이름 아래 저장됩니다. 데이터베이스에는 비밀당
참조 문자열만 저장합니다:

| 비밀 | 참조 |
|--------|-----------|
| 연결 비밀번호 | `dbflux:conn:<profile-id>` |
| 인라인 SSH 비밀번호/패스프레이즈 | `dbflux:ssh:<profile-id>` |
| 저장된 SSH 터널 | `dbflux:ssh_tunnel:<tunnel-id>` |
| 프록시 자격 증명 | `dbflux:proxy:<proxy-id>` |
| 인증 프로필 필드 | `dbflux:auth:<profile-id>:<field>` (필드당 하나) |

### 비밀이 저장되는 경우와 그렇지 않은 경우

- 연결 비밀번호는 **비밀번호 저장**을 선택한 경우에만 저장됩니다. SSH와 프록시 비밀도
  각각의 **저장** 확인란을 선택한 경우에만 저장됩니다.
- 키링을 사용할 수 없으면 DBFlux는 **저장** 확인란을 숨기고 비밀을 저장하지 않습니다.
  세션마다 다시 입력해야 합니다.
- *잠긴* 키링도 사용 가능한 것으로 간주됩니다. 잠금을 해제하기 전에는 쓰기가 실패할 수
  있지만, DBFlux는 비밀 지원을 계속 활성 상태로 유지합니다.

## 세션 및 탭 복원

열려 있는 탭의 종류, 파일 경로, 순서, 활성 탭, 고정 상태는 `dbflux.db`의
`st_sessions` / `st_session_tabs`에 기록됩니다. 복원에 사용되는 스크래치/섀도
사본은 데이터 디렉터리의 `sessions/` 아래에 둡니다. 파일로 저장된 스크립트는 그
파일 자체에 저장됩니다. 자동 저장 주기와 탭을 닫을 때, 그리고 종료할 때입니다.
제목 없는 저장하지 않은 콘텐츠는 세션 폴더에 보관됩니다. 이러한 자동 쓰기는 dbflux
밖에서 변경된 스크립트 파일을 덮어쓰지 않습니다. 그런 쓰기는 거부되며, 저장하지
않은 편집 내역은 편집기(와 세션 폴더 사본)에 그대로 남습니다. `Ctrl+s`와 **다른
이름으로 저장**은 사용자가 요청한 대로 파일을 쓰는 의도적인 동작입니다. 시작 시
**설정 → 일반 → 시작 시 세션 복원**이 켜져 있으면(기본값) DBFlux가 이 세션을
복원합니다.

## 감사 및 개인정보

DBFlux는 중요한 작업(쿼리, 연결, 훅, 스크립트, 설정 변경, MCP/거버넌스 결정)을
`dbflux.db`의 감사 로그에 기록합니다. 이 로그는 기본적으로 개인정보를 보존하도록
설계되어 있습니다:

| 동작 | 기본값 | 효과 |
|----------|---------|--------|
| **쿼리 텍스트 수집** | 끔 | 쿼리 텍스트는 SHA-256 **지문**과 그 길이로 대체됩니다. 전체 텍스트는 감사 행에 저장되지 않습니다. |
| **민감한 값 마스킹** | 켬 | 민감한 패턴(AWS 키, JWT, 자격 증명이 담긴 연결 문자열 등)은 `[REDACTED]`로 대체됩니다. |
| **상세 정보 크기 상한** | 64 KiB | 지나치게 큰 이벤트 페이로드는 작은 부분 엔벨로프로 잘립니다. |

민감한 **JSON 키**(`password`, `token`, `secret`, `api_key`,
`access_key`, `session_token`, `connection_string`, `url`, …)는 패턴 기반 마스킹을
끄더라도 항상 마스킹됩니다.

> [쿼리 기록 관련 주의 사항](#데이터베이스에-저장되는-것)을 기억하십시오. 감사 로그는
> 쿼리 텍스트를 지문으로 저장하지만, *워크벤치 기록*은 전체 텍스트를 저장합니다.
> 둘은 서로 다른 저장소입니다.

전체 이벤트 스키마, 카테고리, 뷰어에 대해서는
[Audit](AUDIT.md)과 [Dashboards & Audit → Audit viewer](DASHBOARDS_AND_AUDIT.md#감사-뷰어)를
참조하십시오.

## IPC/MCP 인증 토큰

DBFlux는 로컬 IPC 표면(MCP 서버와 외부 RPC 서비스가 사용)을 노출합니다. 호출자는
다음 위치에 저장된 토큰으로 인증합니다:

```
<data dir>/dbflux/ipc_auth_token
```

(Linux에서는 `~/.local/share/dbflux/ipc_auth_token`). 이 값은 실행할 때마다 다시
생성되는 무작위 값이며, 소유자 전용 `0600` 권한으로 기록되고, 자식 프로세스를 위해
`DBFLUX_IPC_TOKEN`, `DBFLUX_DRIVER_IPC_TOKEN`, `DBFLUX_AUTH_PROVIDER_IPC_TOKEN`
환경 변수로도 내보내집니다.

이 토큰은 **프로세스 신원 확인 전용**입니다. 이 토큰을 읽을 수 있는 로컬 프로세스라면
무엇이든 연결할 수 있습니다. 추가 인증 계층 없이 IPC/MCP 표면을 localhost 밖으로
노출하지 마십시오. 신뢰 모델은 [AI + MCP Integration](MCP_AI_INTEGRATION.md)을
참조하십시오.

## 백업 및 재설정

DBFlux에는 전용 백업/복원 명령이 없지만, 모든 것이 하나의 파일에 있기 때문에 둘 다
간단합니다.

### 백업

DBFlux를 닫은 상태에서 단일 데이터베이스 파일을 복사합니다:

```
~/.local/share/dbflux/dbflux.db        # Linux (플랫폼에 맞게 조정)
```

이 파일에는 프로필, 기록, 저장된 차트/쿼리, 감사 로그가 들어 있습니다. **비밀은
들어 있지 않습니다.** 비밀은 OS 키링에 있으므로, 다른 기계로 복사한 데이터베이스는
비밀을 다시 입력하기 전까지는 그 기계에 존재하지 않는 키링 항목을 참조합니다.

### 전체 초기화

DBFlux의 데이터를 완전히 지우려면:

1. **데이터 디렉터리**를 삭제합니다(Linux에서는 `~/.local/share/dbflux/`) —
   데이터베이스, 세션 파일, IPC 인증 토큰, SSH known-hosts가 제거됩니다.
2. **이전 버전만 해당:** 레거시 설정 디렉터리(Linux에서는 `~/.config/dbflux/`)가
   아직 남아 있다면 삭제합니다. 현재 버전은 이 디렉터리를 사용하지 않습니다.
3. **키링 항목을 직접 지웁니다.** `dbflux` 서비스 아래의 비밀은 디렉터리를 삭제해도
   OS 키링에 남아 있습니다. 완전히 지우려면 플랫폼의 키링 도구로 제거하십시오.

> 데이터 디렉터리 삭제는 되돌릴 수 없습니다. 프로필이나 기록을 되찾을 가능성이
> 있다면 먼저 `dbflux.db`를 백업하십시오.
