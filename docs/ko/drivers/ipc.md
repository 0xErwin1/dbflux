# 외부 RPC 드라이버

자체 프로세스에서 실행되는 드라이버가 로컬 소켓을 통해 DBFlux에 서비스를 제공할 수 있게 하는
브리지입니다. 이를 통해 DBFlux가 기본 지원하지 않는 데이터베이스를 애플리케이션을 포크하지 않고도
추가할 수 있습니다.

## 한눈에 보기

- **카테고리** — 원격 드라이버가 선언
- **쿼리 언어** — 원격 드라이버가 선언
- **등록 ID** — `rpc:<socket_id>`
- **프로토콜** — 드라이버 RPC 프로토콜 참조 문서를 확인하세요

## 동작 방식

브리지는 특정 데이터베이스에 대한 지식을 전혀 갖지 않습니다. 연결 시 원격 프로세스와 `Hello`
핸드셰이크를 수행하고, 드라이버를 표현하는 데 DBFlux가 필요한 모든 것 — 종류, 메타데이터, 연결 폼 —
은 그 응답으로 돌아옵니다. 이후 브리지는 소켓을 통해 작업을 전달하고 응답을 내장 Rust 드라이버가
구현하는 것과 동일한 핵심 계약으로 변환하므로, 애플리케이션의 나머지 부분은 차이를 알 수 없습니다.

연결 값은 원격 드라이버가 선언한 폼을 키로 삼아 `DbConfig::External { kind, values }`로 저장됩니다.

### 핸드셰이크에서 협상되는 기능

원격 드라이버는 자신이 지원하는 것을 알리고, 브리지가 그에 맞춰 적응합니다:

- `SchemaIntrospection` — 사이드바가 드라이버로부터 스키마 트리를 만듭니다
- `MultiDatabase` — 연결이 둘 이상의 데이터베이스를 노출합니다
- `ChunkedResults` — 큰 결과 집합이 하나의 응답이 아니라 청크로 스트리밍됩니다
- `Cancellation` — 실행 중인 쿼리를 UI에서 취소할 수 있습니다
- `AuditEmit` — 드라이버가 자체 감사 이벤트를 발행할 수 있습니다 (프로토콜 v1.2 이상)

알리지 않은 것은 단순히 인터페이스에 존재하지 않습니다. 이는 내장 드라이버의 설정되지 않은 기능
플래그가 UI에서 기능을 제거하는 방식과 동일합니다.

### 호스트 수명 주기

구성된 RPC 서비스는 DBFlux가 관리할 수 있습니다. 호스트 프로세스는 필요할 때 생성(spawn)되고,
정상 상태를 보고할 때까지 기다린 뒤, 종료를 위해 추적됩니다. 시작 구성이 없는 서비스는 이미 실행
중인 것으로 간주됩니다.

### 감사 전달

`AuditEmit`을 알리는 드라이버는 응답과 섞여서 `EmitAuditEvent` 프레임을 보낼 수 있습니다. 브리지는
이 프레임을 가로채어 호스트의 마스킹 싱크(sanitizing sink)로 보내므로, 외부 드라이버의 이벤트도
동일한 마스킹이 적용된 채 다른 모든 이벤트와 같은 감사 로그에 기록됩니다. 해당 기능을 알리지 않은
드라이버의 프레임은 신뢰하지 않고 폐기합니다.

## 제한 사항

- 호환되는 드라이버 호스트 프로세스와 도달 가능한 소켓이 필요합니다. 브리지는 시작 구성이 없는
  호스트를 시작할 수 없으므로, 사용할 수 없는 서비스는 사용할 수 없는 상태로 남습니다.
- 유효한 기능 집합은 원격 드라이버가 알린 메타데이터와 그 구현에 의해 제한됩니다. 브리지는 드라이버가
  갖지 않은 기능을 절대 추가하지 않습니다.
- 감사 이벤트 발행에는 프로토콜 v1.2 이상과 핸드셰이크의 `AuditEmit`이 필요합니다. 구버전 드라이버는
  아무것도 발행하지 않으며, 그 작업은 DBFlux가 대신 기록하는 이벤트를 통해서만 로그에 나타납니다.
