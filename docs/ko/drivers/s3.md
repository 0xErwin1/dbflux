# Amazon S3

Cloudflare R2와 MinIO를 포함한 AWS S3 및 S3 호환 개체 스토리지입니다.
## 한눈에 보기

- **분류** — 개체 스토리지
- **쿼리 언어** — 개체 브라우저 (쿼리 언어 없음)
- **URI 스킴** — `s3`

[`aws-sdk-s3`](https://crates.io/crates/aws-sdk-s3) SDK를 기반으로 만들어진 DBFlux용 AWS S3 및 S3 호환 개체 스토리지 드라이버입니다. `s3` 기능 플래그 뒤에 게이트되어 있습니다.

## 기능

- `DatabaseCategory::ObjectStorage`로 분류되는 개체 스토리지 드라이버입니다. AWS 프로필/SSO `AuthProfileRef` 또는 정적 액세스 키 자격 증명 중 하나를 통해 AWS S3와 S3 호환 엔드포인트(Cloudflare R2, MinIO)에 연결하며, 엔드포인트 재정의와 path-style 주소 지정을 지원합니다.
- 버킷 탐색: 검색, 새로고침, 버킷 생성을 갖춘 전용 버킷 테이블(이름, 리전, 개체 수, 크기, 버저닝, 생성일). 사이드바는 버킷을 한 수준 깊이의 평면 목록으로 표시합니다.
- 기본적으로 수준별 페이지 나누기로 개체를 탐색합니다(AWS 콘솔 스타일, 드라이버가 반환한 continuation token 사용). 페이지 나누기 없이 전체를 펼치는 선택적 트리 모드 토글도 있습니다.
- 개체 브라우저의 분할 트리/미리 보기 레이아웃: 개체 행은 키, 크기, 스토리지 클래스, 마지막 수정 시각을 보여주고, 디렉터리 행은 하위 개체 수를 보여줍니다.
- 미리 보기 매트릭스: 이미지는 `img()`로 네이티브 렌더링됩니다. 텍스트 계열 개체(txt, md, json, csv, log 등)는 더티 배지, Ctrl+S 저장(`put_object`), 버리기(Discard), 탐색을 벗어날 때의 저장되지 않은 편집 확인을 갖춘 인라인 편집 가능한 버퍼로 열립니다. PDF와 기타 바이너리 개체는 메타데이터 + 다운로드/외부에서 열기로 대체되며, 앱 내 PDF 렌더링은 없습니다.
- 전체 개체 메타데이터(키, 크기, 콘텐츠 타입, 마지막 수정, ETag, 스토리지 클래스, 암호화, 사용 가능한 경우 버전). 스토리지 클래스 스타일링이 STANDARD/STANDARD_IA/GLACIER를 구분하며, 보관(archived)된 개체는 메타데이터 전용으로 저하됩니다(본문 가져오기를 시도하지 않음).
- 구성 가능한 미리 보기 크기 제한. 개체 본문을 가져오기 전에 HEAD 요청으로 확인됩니다.
- CRUD: 단일 개체 삭제, 재귀적 접두사/버킷 삭제(입력으로 확인하는 위험 모달, 요청당 최대 1000개 키의 일괄 처리 `DeleteObjects`), 폴더 생성(0바이트 접두사 마커), 버킷 생성(이름 검증, 리전, 버저닝/퍼블릭 액세스 차단/개체 잠금, 지원되지 않는 엔드포인트에서 우아하게 저하되는 기본 암호화), 단순 스트리밍 업로드(`put_object`/`ByteStream`, 멀티파트 없음), 개체 이름 바꾸기(copy-then-delete, `r`에 바인딩되며 절대 `F2`가 아님).
- Presigned URL: GET/PUT 메서드 선택, 15분/1시간/12시간/7일 만료, URL 복사 작업, 만료와 서명 주체를 밝히는 경고 텍스트.
- 모든 CRUD/변경 작업(업로드, 삭제, 재귀 삭제, 폴더/버킷 생성, 버킷 삭제, 편집 저장, 이름 바꾸기, presign)은 개체 스토리지 `EventCategory` 아래에서 감사되며, 자격 증명과 presigned URL은 절대 로깅되거나 저장되지 않습니다.
- 권한 및 not-found 오류(`AccessDenied`, `NoSuchBucket`, `NoSuchKey`)는 AWS의 일반적인 오류 텍스트 대신 영향받은 버킷/키를 메시지에 밝혀 형식화됩니다.
- 클라이언트 식별자: 모든 요청은 AWS SDK 앱 이름으로 `dbflux-<version>`을 전달하며, CloudTrail의 `userAgent` 필드에서 확인할 수 있습니다.

## 제한 사항

- 멀티파트 업로드와 전용 Transfers 패널이 없습니다 — 업로드는 파일 크기와 무관하게 항상 단일 스트리밍 `put_object` 호출을 거칩니다.
- 내장 PDF 뷰어가 없습니다. PDF와 기타 이미지/텍스트가 아닌 개체는 메타데이터, 다운로드, 외부에서 열기만 제공합니다.
- 수명 주기 규칙이나 ACL 관리가 없으며 S3 Select도 없습니다.
- 이름 바꾸기는 롤백이 없는 copy-then-delete입니다: 성공적인 복사 이후의 삭제가 실패하면 원본과 대상 키가 모두 그대로 남고, 사용자가 삭제를 수동으로 다시 시도해야 합니다.
- `delete_bucket`은 빈 버킷에서만 성공합니다. 비어 있지 않은 버킷의 삭제는 클라이언트 측에서 거부되며, 대신 재귀적 접두사/버킷 삭제 흐름을 안내하는 메시지가 표시됩니다.
- 미리 보기와 메타데이터 표시는 HEAD로 게이트됩니다: 개체의 크기와 스토리지 클래스는 본문 미리 보기를 시도하기 전에 항상 `head_object`로 가져옵니다.
- MinIO 기반 라이브 통합 테스트는 Docker가 필요하며 `cargo nextest run -p dbflux_driver_s3 --run-ignored all`로 실행됩니다.
- 쓰기 권한 프로브가 없습니다: `Connection::probe_write_privilege`는 트레이트 기본값(`WritePrivilege::Unknown`)에 그대로 머뭅니다. 신뢰할 수 있는 확인에는 `iam:SimulatePrincipalPolicy` 권한이 필요한데, 연결하는 역할에는 보통 이 권한이 없기 때문입니다.
